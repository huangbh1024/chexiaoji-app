**v0.1 说明（首版）**

1. 把「添加 / 编辑爱车」从车辆管理页的 Toast 占位升级为**独立二级页**，一个页面同时承载新增与编辑，字段按动力类型动态变化。
2. 明确本页的写入边界：**身份、车牌、里程、动力规格、偏好、提醒**在本页保存；**主驾切换、归档、删除**复用车辆管理的命令，本页只提供主驾开关与「归档此车辆」入口。
3. 修正设计稿与仓库现状的冲突：
   - 设计稿是 3 类动力（纯电 / 插混增程 / 燃油），仓库有 4 类（含油电混动 HEV）；本页改为 **4 段式**，否则现有「凯美瑞双擎」无法编辑（D1）。
   - 设计稿没有「配置版本」与「默认油品」字段，但车库卡片、记账页加油预填都依赖它们；本页各补一个选填字段（D7）。
   - 车牌输入 `maxlength` 与演示值长度不一致；本页按「城市字母 + 5 位（燃油）/ 6 位（新能源）」重新定义（§7.2）。
4. 补齐设计稿缺失的边界：必填校验、车牌重复、里程回退、车库上限、未保存离开、保存失败、车辆已被归档 / 删除、新增首辆车、新增后首页无数据。
5. 明确新增车辆的**空数据看板**：新建车辆没有流水与能耗时，首页、统计、账单、我的页必须显示「暂无数据」而不是伪造 0 能耗或崩溃（§7.8、§9）。
6. 明确 P0 / P1：OCR 证件识别、车型库检索、车辆照片 / 颜色 / VIN / 发动机号、保养周期配置、云端同步为 P1 / P2（§3.2）。

**v0.2 说明（实施）**

1. P0 已按本稿落地：新增 / 编辑页、四类动力动态字段、车牌省份弹层与校验、默认主驾、未保存离开、归档入口、保存 / 失败 / 错误态。
2. 入口已接线：车辆管理顶部与虚线卡、「更多 → 编辑档案」、首页车辆切换器、我的页车库均进入本页；保存后车辆管理页刷新并滚动到该车。
3. 新增车辆的跨页空看板已落地：`Consumption.hasData == false` 显示「暂无能耗记录」，`Maintenance.hasProgress == false` 隐藏进度环；未知车辆不再抛错。
4. 保养提醒按「下次保养里程 − 当前里程」覆盖；无保养流水不显示进度环。
5. 实现差异与文件清单见[技术方案「实施记录」](../technical/vehicle-editor.md#16-实施记录v02)。

## 1. 背景与目标

车辆管理页已经把「看车、切主驾、归档、删除」收进一个页面，但车库的**档案源头**仍然是缺的：

- 车辆管理页的「添加爱车」「添加新座驾」、首页车辆切换器的「添加车辆」、我的页车库的「添加车辆」全部是 `添加车辆页待接入` 的 Toast；
- 车辆卡的「更多 → 编辑车辆档案」也是 `车辆档案编辑待接入`；
- 现有 4 辆演示车是 Mock 种子，用户无法新增一辆真实车辆，也无法修正车牌、里程、电池容量、保险到期等档案字段；
- 记账页的充电 SOC 估算依赖 `batteryCapacityKwh`，加油「加满」估算依赖 `tankCapacityL` 与 `defaultFuelGrade`；这些字段目前只能写死在种子里。

本页要回答五个问题：

1. 我要**新增一辆车**，最少需要填什么？不同动力类型的字段有什么不同？
2. 我的车牌、里程、电池 / 油箱、购车信息、保险到期填在哪里？填错会怎样？
3. 这辆车要不要**设为默认主驾**？设了会影响哪些页面？
4. 我改到一半不想改了，**返回会不会丢数据**？
5. 我把这辆车**归档**了，历史流水和报表还在不在？

设计目标：

- 新增与编辑共用一套表单与校验，不产生两套页面；切换动力类型时字段就地变化，不跳页。
- 必填项少、选填项清楚：不因为「官方电耗」「购车价格」这类非关键数据阻断保存。
- 所有会影响其他页面的字段（名称、车牌、里程、容量、油品、主驾）在保存前就能看到后果说明。
- 车牌输入符合中国车牌习惯：省份选择、自动大写、自动补分隔点、按燃油 / 新能源限制长度。
- 新增车辆没有历史数据时，全 App 有诚实的空状态，不崩溃、不伪造能耗。
- 所有未实现能力（OCR、车型库、云同步）都有明确边界，不出现假成功。

## 2. 用户与典型场景

| 用户 | 关注点 | 本页价值 |
| --- | --- | --- |
| 刚下载的新用户 | 怎么添加第一辆车，最少填什么 | 车库为空时直接进入新增，必填项只有 4 个 |
| 多车家庭 | 新增第二辆车，设为默认主驾 | 主驾开关 + 保存后首页立即切换 |
| 换车用户 | 卖掉旧车、添加新车 | 新增后旧车归档；历史流水仍保留 |
| 刚提车用户 | 车牌还没上、只有临时牌 | 车牌必填的边界与提示（Q6） |
| 注重数据准确的用户 | 电池容量、油箱、油耗、保险到期 | 动态字段按动力类型展示，单位明确 |
| 记账用户 | 充电 SOC、加满估算依赖容量 | 保存后记账页预填立即生效 |
| 手滑用户 | 改到一半返回、重复车牌、里程填小 | 未保存拦截、重复校验、里程回退拦截 |
| 从车库纠错的用户 | 车牌写错、配置写错 | 编辑档案直接修正，所有页面同步 |

典型场景：

- **添加第一辆车**：车库为空 → 首页 / 我的页 / 车辆管理页的添加入口 → 选择「纯电 EV」→ 填品牌车型、车牌、当前里程 → 保存 → 自动成为默认主驾 → 首页看板显示零支出与「暂无能耗记录」。
- **添加第二辆车**：选择「插混/增程」→ 填纯电续航、电池容量、油箱、亏电油耗、默认油品 → 打开「设为默认主座驾」→ 保存 → 首页切到新车，车辆管理页滚动到新车卡片。
- **修正车牌**：编辑「比亚迪 汉 EV」→ 省份选「粤」→ 输入 `BD82K6` → 自动显示 `粤B·D82K6` → 保存 → 账单、统计、车辆选择器同步。
- **卖车归档**：编辑旧车 → 点「归档此车辆」→ 确认弹窗说明继任主驾 → 归档成功 → 返回车库，旧车进入「已归档车辆」。
- **改到一半退出**：改了里程和保险日期，点返回 → 弹层「放弃未保存的修改？」→ 继续编辑 / 放弃修改。
- **重复添加**：输入已存在的车牌 → 保存时提示「该车牌已在车库中」→ 不产生重复车辆。

### 6.2 动力类型选择器

### 6.3 车辆身份信息卡

#### 6.3.1 品牌与车型

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 品牌与车型 | 文本 | 是 | 去首尾空格后 2–40 字符；不允许换行；示例「特斯拉 Model Y 长续航全轮驱动」 |
| 配置版本 | 文本 | 否 | 去首尾空格后 ≤ 30 字符；示例「2023款 创世旗舰型」；为空时车库卡片显示「车辆档案待完善」 |

- 品牌车型输入框：圆角 16、高 48、`bodyLg`；占位符「例如：极氪 001 YOU版」。
- 输入框右侧**不渲染搜索图标**（P0 无车型库，D11）。
- 下方快捷填充胶囊（4 个，横向滚动）：
  - 特斯拉 Model Y、比亚迪 汉 EV、理想 L7 Pro、小米 SU7 Max；
  - 点击把文案填入品牌车型输入框，**不自动修改动力类型或车牌**；
  - 用户可继续编辑；已有内容时点击直接覆盖，覆盖可撤销（输入框系统撤销）。
- 配置版本用于车库卡片副标题与归档卡配置徽标；不参与任何计算。

#### 6.3.2 车牌号码

- 行标题左侧「车牌号码」，右侧「新能源渐变绿牌」+ 44 × 26 开关。
- 左侧省份按钮：显示当前省份简称 + `expand_more`；点击打开省份选择弹层（§6.7）；最小宽 64、高 48、圆角 16。
- 右侧字符输入框：
  - 自动大写；过滤空格、`·`、`•`、`-`；只允许字母与数字；
  - 输入第 1 位后自动在视觉上补「·」（城市字母与后续字符之间）；
  - 燃油牌：城市字母 + 5 位字母数字（规范化后 6 位）；
  - 新能源牌：城市字母 + 6 位字母数字（规范化后 7 位）；
  - 输入框显示「B·DF8932」形式，`letterSpacing` 0.12em，居中；
  - 最大长度按牌型限制；超出时忽略输入，不弹出额外提示。
- 车牌下方 3px 渐变条：新能源绿牌为绿→青，燃油蓝牌为蓝→靛。
- 新能源开关：
  - 打开时按 7 位校验、绿牌渐变；关闭时按 6 位校验、蓝牌渐变；
  - 默认随动力类型（§6.2）；
  - 用户手动切换后，不因动力类型相同而重置。
- 完整车牌 = 省份简称 + 规范化字符（含「·」），如 `粤B·D82K6`；保存与查重均使用规范化完整车牌（去空格、去分隔符、大写）。
- 车牌必填；格式不合法、长度与牌型不一致、与车库其他车辆重复时阻止保存，显示行内错误（§7.2）。
- 编辑态：车牌原样回显；省份与字符拆分；牌型由字符长度推断，用户可切换。
- 新能源车牌字符可以包含 `D`、`F` 等字母；不强制校验「D/F 开头」等地方规则，避免误拒特殊号段（Q6）。
- 允许粘贴完整车牌：若开头为当前省份简称，自动去掉后按字符校验；粘贴文本中的空格与分隔符一并过滤。

- 输入框高 48，`headlineSm` 数字，右侧 `km`。
- 下方说明：`info` 图标 + 「用于核算后续每笔充电/加油后的单公里成本」。
- 编辑态回显该车当前表显里程（含记账页最近一次录入的更高里程）。
- 若输入值小于**最近一次记账里程**，阻止保存并提示「当前总里程不能小于最近记账里程 {n} km」；这是账目一致性的硬约束。
- 等于最近记账里程允许；大于允许。
- 新增时无历史里程，不校验回退。

  - 仅 PHEV / HEV / ICE 展示；EV 隐藏；

  - 用于记账页加油预填；未选择时记账页沿用现有默认值（95），但编辑页不伪造选中态；
  - 设计稿未覆盖，属于补充字段（D7）。
- 购车信息（选填）：
  - 「首次上牌 / 购车时间」：日期选择，范围 1980-01-01 至今天；未来日期阻止保存；
  - 「购车落地价」：万元，0–1000 万元，最多 2 位小数；输入为空表示未录入；
  - P0 只落库并回显，不做折旧 / 残值 / 持有成本计算（D12）。
- 日期字段使用系统日期选择器（主题化），点击整行打开；已选日期显示 `yyyy/MM/dd`，右侧日历图标。
- 价格字段使用小数键盘，右侧单位「万元」；不允许负值。

### 6.5 周期提醒与偏好卡

#### 6.5.1 爱车昵称

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 爱车昵称 | 文本 | 否 | 去首尾空格后 ≤ 12 字符；不允许换行；为空表示不设置 |

- 占位符「给爱车起个亲切名字（如：大白、追风者）」。
- 昵称只作为档案别名：显示在车辆管理卡片与编辑页；**不替换品牌车型**，不改变首页 / 账单 / 统计 / 报表的车辆抬头（D6）。
- 允许与其他车辆重名；不做唯一性校验。

#### 6.5.2 设为默认主座驾

- 行结构：左侧 `star` 图标底盘 + 「设为默认主座驾」+ 副标题「首页仪表盘与单手快捷记账优先展示」；右侧 44 × 26 开关。
- 规则：
  - 车库为空（新增首辆车）：开关强制打开且禁用，说明「首辆车将自动成为默认主驾」；
  - 新增非首辆车：默认关闭；用户可打开；
  - 编辑当前默认主驾：开关打开且**不可关闭**；副标题改为「默认主驾需在车辆管理中切换」，避免本页把主驾置空；
  - 编辑非主驾：开关默认关闭；打开后保存即接管默认主驾；
  - 保存中开关禁用。
- 打开开关时，行下方显示说明：「保存后，首页看板、快捷记账与统计将优先展示该车。」
- 关闭开关不改变当前主驾；若当前车辆是主驾，UI 不允许关闭。
- 主驾切换与车辆管理页「设为主驾」使用同一命令与结果，保存成功后首页立即切换。

#### 6.5.3 下次保养里程

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 下次保养里程 | 整数 | 否 | 0–9,999,999 km；右侧单位 `km` |

- 语义为**绝对表显里程**，不是「还剩多少公里」。
- 剩余里程 = 下次保养里程 − 当前总里程；≤ 0 显示「已超期」。
- 小于或等于当前总里程时允许保存，但显示警示「将显示为已超期」；不阻断（用户可能在补录已超期保养）。
- 未填时：不生成该车的保养提醒；首页保养卡显示「设置保养提醒」入口。
- 没有保养流水时，首页保养卡不显示进度环，只显示剩余 / 超期文案（D9）。

#### 6.5.4 车险到期时间

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 车险到期时间 | 日期 | 否 | 1980-01-01 至 2100-12-31 |

- 用于车辆管理卡的「车险剩余」与提醒行。
- 允许选择过去日期（补录已过期保单），但显示警示「已过期」；不阻断保存。
- 未填时：车辆管理卡第三指标显示「— / 未录入」，不伪造剩余天数。

### 6.6 底部操作栏

- 固定在页面底部，背景 `surface` 90% + 毛玻璃，顶部 1px 分隔；左右 16 + 安全区。
- 纵向排列：
  1. 主按钮：
     - 新增：「保存并添加到车库」；
     - 编辑：「更新并保存档案」；
     - 高 52、圆角 999、主色底、`onPrimary` 文字、左侧 `check_circle` 图标；
     - 点击触发完整校验（§6.10）。
  2. 编辑态：「归档此车辆」文字按钮，危险色、`inventory_2` 图标、高 44 触控区；新增态隐藏。
- 保存中：主按钮显示 16 圆形进度 + 「正在保存…」，禁用；归档按钮禁用；返回被拦截。
- 保存失败：主按钮上方显示行内错误（危险色 `bodySm`，`liveRegion`），表单内容不丢失；按钮恢复可点。
- 键盘弹出：操作栏固定在键盘上方（`bottomInset = max(viewInsets.bottom, safeArea.bottom)`），内容区自动滚动，避免遮挡当前字段。
- 按钮触控区 ≥ 48；主按钮与归档按钮间距 4–8。

### 6.7 省份选择弹层

- 底部滑入，顶部圆角 32，最大高度 85%，内容可滚动；顶部拖拽把手 40 × 4。

  `粤 京 沪 浙 苏 川 鲁 豫 鄂 湘 闽 皖`。
- 「全国省市全览」：31 个省市区、7 列 5 行：
  `京 津 冀 晋 蒙 辽 吉 黑 沪 苏 浙 皖 闽 赣 鲁 豫 鄂 湘 粤 桂 琼 渝 川 贵 云 藏 陕 甘 青 宁 新`。

- 点击任一省份：立即回填省份按钮、关闭弹层、Toast「已选择车牌简称「{省}」」。

- P0 不提供搜索；省份数量少，搜索收益低（P1 视需要）。

### 6.8 未保存离开拦截

- 触发条件：表单当前值与初始值不一致（`isDirty`），且用户点击顶部返回 / 系统返回 / 归档。
- 弹层结构：
  - 图标 48 圆形、警示色 14% 底、`edit_note` 图标；
  - 标题「放弃未保存的修改？」；
  - 正文「当前填写的内容尚未保存，离开后将丢失。」；
  - 按钮：「继续编辑」（中性底）/「放弃修改」（危险实心）。
- 「继续编辑」关闭弹层，停留在表单；「放弃修改」执行原始动作：
  - 返回：`Navigator.pop(null)`；
  - 归档：继续打开归档确认弹层（§6.9）。
- 无修改：直接返回 / 直接归档，不弹层。
- 保存中：不允许返回；`PopScope(canPop: false)`，主按钮与归档均禁用。
- 保存成功后：先清空 `isDirty`，再 `pop(result)`，不触发拦截。
- 编辑加载失败 / 车辆不存在：无表单，不触发拦截，可直接返回。

### 6.9 从编辑页归档

- 仅编辑态显示「归档此车辆」。
- 点击：
  - 若表单有未保存修改：先走 §6.8 的放弃修改弹层；选择「放弃修改」后继续打开归档确认；
  - 若无修改：直接打开归档确认。
- 归档确认复用车辆管理页的 `showArchiveVehicleSheet`：
  - 标题「将「{车名}」归档？」；
  - 正文「归档后该车辆将移出常用车库，首页仪表盘与快捷记账不再展示；历史流水、报表与凭证完整保留，可随时在「已归档车辆」恢复。」
  - 若该车是默认主驾且还有其他在库车辆：追加「归档后，默认主驾将由「{继任车名}」接任。」
  - 若该车是唯一在库车辆：追加「归档后车库将为空，首页与快捷记账将显示空状态。」
  - 按钮「取消」/「确认归档」。
- 归档成功：
  - 弹层关闭；
  - 本页 `pop(VehicleEditorResult(archived: true))`；
  - 本页 `pop` 前 Toast「已将「{车名}」归档」；车辆管理页刷新；
  - 若车库为空，车辆管理页显示空车库状态；
  - 历史流水与报表不变。
- 归档失败：弹层保持，显示错误文案，按钮恢复；本页不退出。
- 归档不要求先保存表单；未保存的修改按 §6.8 明确丢弃，避免「归档了旧数据但界面显示新数据」的错觉。

### 6.10 保存流程

1. **校验**：点击主按钮后，按 §7 规则校验全部字段。
   - 第一个错误字段滚动到可视区并获得焦点；
   - 字段错误显示在对应输入框下方；
   - 顶部副标题变为「有未保存的修改」或保持错误提示；
   - 不调用接口。
2. **提交**：
   - 新增：`createVehicle(draft)`；
   - 编辑：`updateVehicle(vehicleId, draft)`；
   - 提交期间禁用全部字段、主按钮、归档、返回；主按钮显示进度。
3. **成功**：
   - 失效车库 / 车辆列表 / 首页 / 账单 / 统计 / 我的页 / 报表等（见技术方案 §7.4）；
   - 新增：无论是否设为主驾，保存后选中新车；
   - 编辑：仅当本次接管主驾时选中该车，否则保持当前选中；
   - `pop(VehicleEditorResult(vehicleId, created, archived: false))`；
   - 来源页刷新；若来源为车辆管理页，则滚动到该车卡片；
   - Toast：
     - 新增且设为主驾：「「{车名}」已添加到车库，并设为默认主驾」；
     - 新增未设主驾：「「{车名}」已添加到车库」；
     - 编辑且接管主驾：「「{车名}」档案已更新，并设为默认主驾」；
     - 编辑未改主驾：「「{车名}」档案已更新」。
4. **失败**：
   - 字段级错误（服务端返回）：映射到对应字段，滚动到第一个错误；
   - 表单级错误：主按钮上方显示；
   - 不退出页面、不清空表单、不产生乐观假成功；
   - 错误文案见 §8.3。

保存成功后，以下内容立即在全 App 生效：

| 变更 | 影响 |
| --- | --- |
| 品牌车型 / 配置版本 / 昵称 | 车辆管理卡片、车辆选择器、车辆切换器、账单 / 统计 / 报表车辆抬头 |
| 车牌 | 车辆管理、车辆选择器、归档卡、删除确认、单笔详情车辆快照 |
| 当前总里程 | 首页车辆卡、车辆管理三指标、统计 / 账单最近读数、下次保养剩余 |
| 电池容量 / 油箱容量 / 默认油品 | 记账页充电 SOC、加满估算、加油单价预填 |
| 动力类型 | 首页能耗卡口径、统计指标、账单分类建议、车辆卡颜色与图标 |
| 主驾 | 首页看板、快捷记账默认车辆、统计初始筛选 |
| 保险 / 保养 | 车辆管理提醒行、首页保养卡、统计保养卡 |

## 7. 数据口径与格式化

### 7.1 车辆身份与别名

- `name`（品牌车型）：必填，去首尾空格，长度 2–40；全 App 的车辆主标题。
- `specLabel`（配置版本）：选填，≤ 30；为空时车辆管理卡与归档卡显示「车辆档案待完善」，不自动拼接不存在的配置。
- `nickname`（爱车昵称）：选填，≤ 12；为空表示不设置；不替换 `name`。
- 名称与昵称允许重复；车牌不允许重复。
- 名称、配置、昵称均不参与金额 / 能耗计算。

### 7.2 车牌规则

**规范化**：

1. 去首尾空格；
2. 去除所有空格、`·`、`•`、`-`；
3. 字母转大写；
4. 保留省份简称之外的字符作为 `plateBody`；
5. 展示时在 `plateBody` 第 1 位后插入 `·`。

**格式**：

| 牌型 | 规范化长度 | 正则 | 示例 |
| --- | --- | --- | --- |
| 燃油蓝牌 | 6（城市字母 + 5） | `^[A-Z][A-Z0-9]{5}$` | `粤B·D82K6` |
| 新能源绿牌 | 7（城市字母 + 6） | `^[A-Z][A-Z0-9]{6}$` | `粤B·DF8932` |

- 省份简称必须是 31 个省市自治区简称之一；不含港澳台。
- 城市字母必须是 `A–Z`；后续字符允许 `A–Z` 与 `0–9`。
- 输入时自动大写、自动过滤分隔符；不强制按 `D/F` 开头等号段规则（Q6）。
- 新能源开关决定长度与渐变；切换开关后若长度不匹配，行内提示「当前字符数与新能源 / 燃油牌不一致，请修改」。
- 切换动力类型自动设置开关，但用户手动选择优先（§6.2）。

**唯一性**：

- 以规范化完整车牌（省份 + 城市字母 + 5/6 位）比较，忽略大小写与分隔符；
- 新增时与全部**在库 + 归档**车辆比较，避免恢复后冲突；
- 编辑时排除自身；
- 重复时提示「该车牌已在车库中（{车名}）」，阻止保存。
- 客户端即时提示至少覆盖在库车辆；归档车辆可能与在库车辆冲突，由服务端在保存时做全量校验（含归档）。

**边界**：

- 车牌必填；空车牌不能保存。
- 临时牌 / 无牌新车 P0 不支持录入，需产品确认是否放开（Q6）。
- 使馆、警用、军牌等特殊号段 P0 不特殊适配，按上述正则校验。

### 7.3 当前总里程

- 必须为整数，0–9,999,999 km。
- 编辑态显示值 = `max(档案里程, 最近一次记账里程)`；保存时若小于最近记账里程，阻止保存（§6.3.3）。
- 允许大于最近记账里程；保存后首页、车辆管理、统计的当前里程取新值。
- 不允许负数、小数、空白。
- 新增车辆无流水时，里程就是唯一基准。

### 7.4 动力规格

- 所有规格字段选填；未填表示「未录入」，不补默认值、不参与计算。
- 字段与动力类型的适用关系：

| 字段 | EV | PHEV | HEV | ICE | 下游用途 |
| --- | --- | --- | --- | --- | --- |
| 电池容量 `batteryCapacityKwh` | ✅ | ✅ | — | — | 充电 SOC 估算、充满提示 |
| 官方百公里电耗 | ✅ | — | — | — | 仅档案展示 / 参考，不参与账单 |
| 纯电续航 `electricRangeKm` | — | ✅ | — | — | 仅档案展示 / 参考 |
| 油箱容积 `tankCapacityL` | — | ✅ | ✅ | ✅ | 加满估算 |
| 亏电 / 综合 / 标称油耗 | — | ✅（亏电） | ✅（综合） | ✅（标称） | 仅档案展示 / 参考，不覆盖实际能耗 |
| 默认油品 `defaultFuelGrade` | — | ✅ | ✅ | ✅ | 记账页加油单价预填 |

- 范围与精度见 §6.4；超出范围阻止保存。
- 数据层统一存为一个选填字段 `officialConsumption`（官方电耗 / 亏电油耗 / 综合油耗 / 标称油耗），单位与展示标签由动力类型决定；不重复存四份。
- 实际能耗永远来自流水，不用官方标称值替代（不伪造）。
- 修改容量 / 油品只影响之后的记账预填，不回溯修改历史流水。

### 7.5 默认主驾

- 全 App 唯一：`primaryVehicleId` 同一时刻只能指向一辆在库车辆。
- 规则：
  - 车库为空时新增：自动成为主驾，开关强制开启；
  - 新增非首辆车：默认不接管，用户打开开关则接管；
  - 编辑当前主驾：保持主驾，不允许在本页关闭；
  - 编辑非主驾：可打开开关接管；
  - 归档主驾：由继任车辆接管（车辆管理既有规则），本页不静默改主驾。
- 保存成功且接管主驾后：首页看板、快捷记账默认车辆、统计初始筛选切到该车；已打开的账单 / 统计筛选不强制重置（沿用现有归一化规则）。

### 7.6 周期提醒

**下次保养里程**：

- 剩余里程 = `nextMaintenanceKm − 当前总里程`。
- `remaining < 0`：已超期，显示「已超期 {n} km」。
- `0 ≤ remaining ≤ 1000`：即将保养（警示）。
- `remaining > 1000`：正常。
- 没有保养流水时，首页保养卡不显示进度环，只显示剩余 / 超期文案；有保养流水时按「上次保养里程 → 下次保养里程」计算进度。
- 未填：不生成保养提醒；首页显示「设置保养提醒」入口。

**车险到期时间**：

- 剩余天数 = `insuranceExpiry − 今天`（按本地日期差，不含时分秒）。
- `days < 0`：已过期；`0 ≤ days ≤ 30`：即将到期；其余正常。
- 未填：车辆管理卡第三指标显示「— / 未录入」。

### 7.7 购车信息

- 购车日期：日期，1980-01-01 至今天；未来日期阻止保存。
- 购车落地价：万元，0–1000，最多 2 位小数；全链路按整数分存储（`purchasePriceCents`），展示时换算为万元。
- P0 只落库、回显；不计算折旧、残值、每公里折旧、持有成本。
- 未填不显示「¥0」，显示「未录入」。

- 新建车辆没有流水、能耗、保养记录时：
  - 首页：本月支出 `¥0`、单公里成本 `¥0`、能耗卡显示「暂无能耗记录」、保养卡显示「设置保养提醒」、趋势 / 分类 / 最近记录为空态；
  - 统计：概览为 0 / 空，趋势与分类为空态，不崩溃；
  - 账单：车辆筛选可选该车，列表为空；

  - 不显示官方标称电耗 / 油耗冒充实际能耗。

### 7.10 空值与反常数据

- 规格字段为空：保存为 `null`，下游显示「未录入」；不补 0。
- 配置版本为空：车辆卡显示「车辆档案待完善」。
- 昵称为空：不显示昵称胶囊；不写入空字符串。
- 购车价格为空：不写入 0；显示「未录入」。
- 保养里程 ≤ 当前里程：允许保存，显示「将显示为已超期」。
- 保险日期已过：允许保存，显示「已过期」。
- 编辑时车辆已被删除 / 归档：显示错误态或保存失败提示，不回写。
- 最近记账里程高于档案里程：编辑页以最近记账里程为显示值；保存更低值被阻止。
- 服务端返回的字段错误优先于客户端校验结果展示；两者一致时只显示一条。

### 8.3 错误码

| HTTP | code | 场景 | 前端处理 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 字段格式 / 范围错误 | 按 `field` 映射到行内错误，滚动到第一个错误 |
| 409 | `PLATE_ALREADY_EXISTS` | 车牌重复（含归档车辆） | 车牌行内错误「该车牌已在车库中（{车名}）」 |

| 404 | `VEHICLE_NOT_FOUND` | 编辑的车辆已被删除 | 错误态 / 保存失败提示，引导返回车库刷新 |
| 409 | `VEHICLE_ARCHIVED` | 编辑的车辆已被归档 | 「该车辆已归档，请在已归档车辆中恢复后再修改」 |

| 409 | `PRIMARY_LOCKED` | 试图关闭当前主驾 | 「默认主驾需在车辆管理中切换」 |
| 500 | `INTERNAL` | 其他 | 「保存失败，请重试」 |

### 8.4 客户端容错

- 客户端校验是第一道体验防线，服务端必须再次校验；客户端校验结果不作为唯一安全 / 一致性边界。
- `VALIDATION_FAILED` 的 `field` 使用与客户端一致的字段名；未知字段归入表单级错误。
- 新增接口幂等：同一 `requestId` / 同一车牌重复提交返回同一 `vehicleId`，客户端以响应为准。
- 更新接口带 `version`；冲突时不覆盖，提示刷新。
- 保存成功后不再请求详情；以响应 + 本地失效刷新为准。
- 接口未确认前由 Mock 仓库提供内存实现，UI 与 provider 不感知实现。
- 所有金额字段为整数分；所有里程为整数 km；日期使用 `yyyy-MM-dd`（本地日期，不带时区偏移）。

## 9. 全局状态与异常

- **单一数据源**：车辆列表、默认主驾、归档状态、档案字段只由 `VehicleStore` / 车辆仓库持有；本页不维护第二份车辆数组。
- **跨页失效**：新增 / 更新 / 归档成功后，失效车库、车辆列表、首页看板与记录、账单列表与汇总、统计概览 / 趋势 / 分类、我的页车库、月度报表、归档列表。
- **作用域归一化**：
  - 新增且接管主驾：选中车辆切到新车；
  - 编辑当前选中车辆：保持选中；
  - 归档当前选中车辆：回退到继任主驾或 `null`；
  - 账单 / 统计 / 我的页筛选指向被归档车辆时，按既有规则回退。
- **新增车辆空数据**：全 App 按 §7.8 显示空态；不允许因缺少 dashboard / 流水抛异常。
- **并发**：同一时刻只允许一个保存；`isSaving` 期间按钮禁用、返回拦截；服务端版本冲突保留用户输入。
- **离线**：不做离线队列；保存失败显示网络错误，不产生乐观假成功。
- **空车库**：新增首辆车自动成为主驾；所有页面从空态切到有车状态。
- **登录 / 多账号**：当前无账号体系；接入后车辆归属账号，切换账号清空本地缓存与编辑态。
- **性能**：本页无列表请求；编辑详情一次请求，保存一次写入；不因大表单造成掉帧。

## 13. 待确认问题

| # | 问题 | 影响 | 本文档建议 |
| --- | --- | --- | --- |
| Q1 | 设计稿 3 类动力，是否接受 4 类（含 HEV）？ | 表单结构与现有车辆可编辑性 | 接受 4 类；HEV 与 ICE 共用油箱 + 油耗字段。若产品坚持 3 类，需把 HEV 归入燃油并保留只读 HEV 标记 |
| Q2 | 车牌是否允许临时牌 / 无牌新车？ | 新增可用性 | P0 必填标准车牌；临时牌支持需产品确认号牌格式与校验规则 |
| Q3 | 车牌唯一性是否包含归档车辆？ | 归档后重新添加 | 包含；否则恢复时冲突。若产品希望归档后复用，需定义冲突解决流程 |
| Q4 | 默认主驾在新车保存时是否默认开启？ | 用户预期 | 新增默认关闭；首辆车强制开启；编辑主驾不可关闭 |
| Q5 | 配置版本是否作为正式字段？ | 车库副标题 | 作为选填字段；若产品希望自动从车型库带出，放 P1 |
| Q6 | 默认油品是否在本页维护？ | 记账预填准确性 | 是；PHEV / HEV / ICE 显示，选填；未选沿用记账页默认 95 |
| Q7 | 昵称的展示范围？ | 字段价值 | P0 车辆管理卡片 + 编辑页；不替换车名，不改首页 / 报表抬头 |
| Q8 | 购车日期 / 价格是否 P0？ | 表单长度 | P0 选填落库；折旧 / 持有成本 P1；若不需要可隐藏但保留字段 |
| Q9 | 新增车辆无流水时首页如何展示？ | 空态完整性 | 零支出 +「暂无能耗记录」；不伪造能耗、趋势、保养周期 |
| Q10 | 保养提醒是否只按里程？ | 提醒准确性 | P0 只按「下次保养里程 − 当前里程」；时间周期与保养项目 P1 |
| Q11 | 归档入口是否放在编辑页？ | 操作路径 | 保留；复用车辆管理确认弹层；脏表单先确认丢弃 |
| Q12 | 车辆上限是否为 10？ | 添加入口 | 沿用现有 10 辆上限；达到上限置灰并提示归档 |
| Q13 | 车型库 / OCR 的优先级？ | 录入效率 | P1；P0 文本 + 4 个快捷填充 + OCR Toast 占位 |
| Q14 | 深色稿是否补齐？ | 视觉验收 | 按 `AppPalette.dark` 推导，待设计复核 |

## 14. 后续迭代方向

- OCR 证件识别：行驶证 / 发票拍照，识别品牌车型、车牌、VIN、购车日期并回填。
- 车型库检索：品牌 / 车系 / 年款 / 配置三级联动，自动补全电池、油箱、官方能耗。
- 车辆照片、颜色、VIN、发动机号、行驶证照片。
- 保养周期与保养项目配置，按时间 + 里程双维度提醒。
- 保险险种、保额、保险公司与续保提醒。
- 折旧 / 残值 / 持有成本分析（购车价 + 流水 + 里程）。
- 车辆导入 / 导出、跨账号迁移。
- 云端同步与多端档案。
- 车辆生命周期时间线（购买、上牌、保险、保养、归档）。
