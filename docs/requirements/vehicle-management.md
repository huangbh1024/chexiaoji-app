**v0.1 说明（首版）**

1. 本页是车库的**唯一写入口**：默认主驾、归档、恢复、删除都在这里完成（排序 P1 也归本页）；我的页与首页只做只读展示。
2. 明确「默认主驾（默认车辆）」全 App 唯一，且是首页看板、记账默认车辆、统计初始筛选的来源。
3. 把「归档」与「删除」拆成两种语义：**归档 = 软移除，保留全部流水，可恢复；删除 = 永久移除，仅允许对无流水车辆执行**（§7.4）。
4. 补齐设计稿缺失的边界：删除默认主驾、归档默认主驾的继任、车库为空、唯一车辆、归档恢复入口。
5. 修正设计稿三张卡的文案不一致：三按钮统一为「记一笔 / 能耗统计 / 编辑档案」与「记一笔 / 设为主驾 / 编辑档案」；右侧状态统一为「本月产生支出」。
6. 明确 P0 / P1：P0 交付列表、汇总、主驾切换、归档 / 恢复、删除（无流水）、空错态；添加 / 编辑爱车页、拖拽排序、车联网同步为 P1。
7. 设计稿的底部导航与中央 FAB 是画布通用壳；本页作为二级页不重复渲染（与账单详情、月度报表一致）。

**v0.2 说明（实施）**

1. P0 已按本稿实现：车库总览、车辆成员卡、设为默认主驾、归档 / 恢复、删除拦截、空车库与错误态。
2. 入口已接入：首页「管理车辆」、我的「管理爱车」、单笔详情车辆箭头；统计车辆弹层的添加入口仍为 P1。

5. 删除有流水车辆在 P0 被拦截并引导归档；删除仅对无流水车辆开放。
6. 实施差异与文件清单见[技术方案「实施记录」](../technical/vehicle-management.md#16-实施记录v02)。

**v0.3 说明（归档页拆分）**

1. 「已归档车辆」由本页的恢复弹层升级为独立二级页，详见[已归档车辆需求](archived-vehicles.md)；本页只保留入口工具卡与归档动作。
2. 归档车辆的恢复、查看历史报表与彻底删除统一在新页面完成；本页不再承载归档车辆的写操作。
3. 在库车辆的删除规则不变：默认主驾（多车）与有流水车辆仍被拦截并引导归档；归档后的彻底删除走新页面的双因子强确认。
4. 彻底删除的语义为「销毁车辆档案 + 历史流水解除车辆归属」，账单总额不变；若产品改为级联删除，需同步修订本页 §7.4 与新页面文档。

## 1. 背景与目标

「我的」页的车库回答「我有哪些车、它们现在怎么样」，首页车辆卡回答「当前这辆车花了多少」，但两者都只能看、不能管：无法新增车辆、无法切换默认主驾、无法把卖掉的车移出车库，更无法纠正误添加的记录。当前所有相关入口都只是 `车辆管理页待接入` 的 Toast。

本页把「**车队的增、删、改、排序与主驾归属**」收进一个页面：顶部是车队资产总览，其下逐车列出关键指标与提醒，每辆车提供记账、统计、档案入口，右上角「更多」承载设为主驾、编辑、归档、删除。所有写操作都必须回答两个问题：**会影响哪些页面**、**数据会不会丢**。

设计目标：

- 首屏即可看到「车队总体状况 + 第一辆车」，向下滚动逐车管理，不需要先进入车辆详情。
- 默认主驾在视觉、排序和操作上都是明确的「一等公民」，但其他车辆仍可一键切换。
- 归档与删除的后果一目了然：归档可恢复、保留流水；删除不可撤销、仅限无流水车辆。
- 空车库、唯一车辆、删除主驾、归档主驾等边界都有确定的界面与文案，不出现死路。
- 复用首页 / 我的页 / 账单页的 token 与组件，不产生第二套卡片、胶囊、图标规范。
- 所有未接入的数据（SOH、保险、年检、车联网）都有「未录入 / 暂无」的诚实表达。

## 2. 用户与典型场景

| 用户 | 关注点 | 本页价值 |
| --- | --- | --- |
| 单车车主 | 总里程、本月支出、保养提醒、默认车辆 | 一眼确认车况与开销，误添加时可删除 |
| 多车家庭 | 车队总览、动力构成、逐车指标 | 在一个页面比较、切换主驾、归档卖掉的车 |
| 公司 / 车队用户 | 车队总开销、每辆车本月支出 | 汇总口径与账单一致，便于对账 |
| 刚记账的新用户 | 如何添加第二辆车 | 顶部与列表底部都有添加入口 |
| 需要纠错的用户 | 删除误添加或已卖掉的车 | 归档保留历史；无流水车辆可永久删除 |
| 注重账目完整的用户 | 删除会不会带走流水 | 弹窗明确「流水保留 / 不可删除原因」 |

典型场景：

- **换主车**：买了新车，把旧车归档；旧车历史流水仍能在账单里查到。
- **多车对比**：在车队总览看合计里程与本月开销，再逐车看电耗 / 油耗与保养提醒。
- **误添加**：添加了一辆重复的车，因无流水直接删除。
- **卖掉旧车**：卖掉但有大量历史记录，选择归档；需要时从「已归档车辆」恢复。
- **保养前**：在默认主驾卡上直接看到「下次小保养：约 1,574 km 后」，并点「记一笔」记下本次保养。
- **月末核对**：车队总开销与账单页「全部车辆」同月合计一致，不用两处对账。

## 6. 模块需求

### 6.1 顶部栏

- 左侧：36 × 36 圆形返回按钮（`surface` 底、`shadow` 轻描边、`arrow_back_ios_new`），点击 `Navigator.pop`；拦截返回时若有未完成的写操作（保存中）则忽略返回。
- 中间：标题「车辆管理」（`headlineMd`）；副标题「名下在库 {n} 辆座驾 · {健康短语}」（`bodySm`、`outline`）。
  - 健康短语：无预警「资产健康良好」；有预警「{m} 项待处理」；数据加载失败「数据待刷新」。
  - `n` 只统计在库车辆，不含已归档。
- 右侧：「添加爱车」胶囊按钮（主色底、白字、`add` 图标 16、左右 14 / 上下 8）。P0 点击 Toast「添加爱车页待接入」；P1 进入添加页。
- 吸顶：`SliverPersistentHeader` + `BlurredHeaderDelegate`，底色 86% + 16px 模糊；滚动时底部分隔线渐显。
- 副标题过长时单行省略，不换行；按钮文案固定 4 字，不截断。

### 6.2 车库资产总览卡

**结构**

1. 顶部行：圆形车库图标（28 × 28，白色 20% 底）+「车库资产总览」；右侧健康徽标。
2. 两块指标：累计行驶里程、本月车队总开销，各占一半；半透明深色底（黑 10%）+ 白色 15% 描边 + 16 圆角。
3. 底部分隔线 + 动力构成行：彩点 + 「纯电 n 辆」等，段间竖线分隔。

**规则**

- 累计行驶里程 = 全部在库车辆 `odometerKm` 之和，千分位 + `km`；无车辆时显示 `0 km`。
- 本月车队总开销 = 当月自然月内、全部在库车辆、全部类别支出之和；与账单页同月「全部车辆」合计一致。金额 `¥` 小一号、数值大号、无小数（千分位），超过 7 位时用 `FittedBox` 缩放。
- 动力构成：按 纯电（ev）→ 插混（phev）→ 油混（hev）→ 燃油（ice） 顺序，只显示数量 > 0 的组；组间 `|` 分隔；无车辆时整行隐藏。
- 健康徽标：
  - `pendingIssueCount == 0` 且至少一辆车有提醒数据 → 「全部在库良好」，白色 20% 底。
  - `pendingIssueCount > 0` → 「{n} 项待处理」，琥珀底（`secondaryContainer`）。
  - 无任何提醒数据 / 加载失败 → 不显示徽标，避免伪造。
- 卡片整体可点击：滚动到「车队成员」区块顶部；不可点击进入其他页面。
- 加载中：卡片外框保留，数值与构成显示骨架条。
- 错误：保留外框与标题，数值显示「—」，右上角不显示健康徽标；错误提示由页面级 §6.12 处理。

### 6.3 车队成员区块

- 标题行：左侧 4 × 16 主色圆角强调条 +「车队成员」（`headlineSm`）；右侧「共 {n} 辆」（`bodySm`、`outline`）。
- P0 **不展示**「长按卡片可调换顺序」；P1 支持拖拽后再显示，并支持「重置顺序」。
- 排序：默认主驾固定第一；其余按 `sortOrder` 升序；归档车辆不在此列表。P1 拖拽只调整非主驾之间的顺序，主驾始终置顶（或允许拖到首位并触发设为主驾，二选一，P1 确认）。
- 每张卡之间 12 间距；卡片圆角 32。
- 列表为空时展示 §6.12 空态；区块标题仍显示「共 0 辆」。

### 6.4 车辆成员卡

#### 6.4.1 通用结构

1. **头部**：44 × 44 圆角 16 动力图标容器（动力色 15% 底 + 动力色图标 24）；车名（`headlineSm`）+ 状态徽标；右下第二行：车牌胶囊 + 副标题；最右「更多」按钮（32 × 32，`more_vert`，点击打开 §6.7）。
2. **指标区**：三列等宽，上下 1px 分隔线，垂直内边距 16；每列：标签（`bodySm`）+ 数值（`labelLg`，700）+ 单位（10/12）。
3. **提醒行**：左侧图标 + 文案（最紧迫一项）；右侧「本月产生支出：¥{金额}」；两者在窄屏可换行，间距 8。
4. **操作行**：三等分按钮，高 36，间距 8，全圆角。
5. **默认主驾态**：1px `primary` 25% 描边 + 主驾阴影；车名后显示「默认主座驾」主色徽标；操作行第一按钮为「记一笔」，主色浅底。
6. **普通态**：1px `outlineVariant` 60% 描边 + 普通阴影；操作行第一按钮为「设为主驾」。
7. 点击卡片空白区域：P0 无操作（不进入详情）；点击车名无操作；更多按钮与操作按钮各自 `stopPropagation`。

#### 6.4.2 动力类型与指标

| 动力 | 槽 2（能耗） | 槽 3（健康 / 归属） | 说明 |
| --- | --- | --- | --- |
| 纯电 ev | 动力电耗 `kWh/百公里` | 电池健康 SOH `%` | SOH 缺失显示「—」+「未录入」 |
| 插电混动 phev | 动力电耗 `kWh/百公里` | 亏电油耗 `L/100km` | 设计稿槽 2 为纯电续航，P1 有电量 / 续航数据后替换 |
| 油电混动 hev | 综合油耗 `L/100km` | 车险剩余 `天到期` | 无保险数据时槽 3 显示「—」 |
| 燃油 ice | 综合油耗 `L/100km` | 车险剩余 `天到期` | 同上 |

- 槽 1 固定「当前里程」，取 `odometerKm`；单位 `km`。
- 数值颜色：里程 `onSurface`；能耗用动力色；SOH 正常 `onSurface` + 主色状态点，低于 80% 用 `error`；车险剩余 ≤ 30 天用 `error`，否则 `secondary`（`secondaryText`）。
- 数值缺失：显示「—」，下方单位位置显示「未录入」/「暂无数据」，不隐藏整列，避免三列宽度跳动。
- 三列文本不换行；数值超过 6 字符时 `FittedBox` 缩放。

#### 6.4.3 提醒行

- 左侧提醒按**紧迫度**取最紧迫的一项：
  1. 保养超期：`Maintenance.isOverdue` → 「保养已超期 {abs(km)} km」，`error`。
  2. 保险 / 年检 30 天内到期：取剩余天数更少者 → 「交强险+商业险 {n} 天后到期」/「年检 {n} 天后到期」，`error`。
  3. 保养预警：`Maintenance.isWarning` → 「下次小保养：约 {km} km 后」，`secondary`。
  4. 保养正常：`Maintenance.enabled` → 「下次小保养：约 {km} km 后」，`outline`。
- 设计稿中「车险剩余 48 天」属于第三指标槽位（§6.4.2），不进入提醒行；只有 ≤ 30 天才升级为提醒。
- 无任何提醒数据：不显示左侧提醒，右侧本月支出左对齐。
- 图标：保养 `build_circle`、保险 `verified_user`、年检 `schedule`，颜色与文案一致。
- 右侧固定「本月产生支出：¥{金额}」，取该车当月全部类别支出；金额无值时显示「¥0.00」。
- 设计稿中的「上次加油 ¥420.00 (6/12)」「综合续航 920 km」属于 P1 补充信息，本期不与本月支出争抢同一行。

| --- | --- | --- | --- |
| 默认主驾 | 记一笔（主色浅底） | 能耗统计 | 编辑档案 |

### 6.6 车机车联同步（P1，本期不展示）

- P0 不渲染设计稿底部的「车机车联数据实时同步」卡，也不在别处展示「已接入」「待授权」等未实现状态。

- 确认弹窗：图标（动力色 15% 底 + 动力图标）、标题「将 {车名} 设为默认主驾？」、正文「设为默认后，首页看板、快捷记账及能耗统计将优先展示该车辆数据。」、按钮「取消」/「确认设为主驾」。
- 确认后：
  - 默认主驾全库唯一：原主驾取消徽标与高亮，新主驾获得「默认主座驾」徽标、主色描边与阴影，并移到列表第一位。
  - 操作行按钮随状态切换（不重建整卡）。
  - 首页 `selectedVehicleIdProvider` 立即切到新车；记账页下次打开默认该车；统计页保持用户当前筛选（Q11）。
  - Toast「已将 {车名} 设为默认主驾」。
  - 失败：弹窗保持打开，显示错误文案「设置失败，请重试」；按钮恢复可点。
- 当前已是默认主驾：不展示「设为主驾」按钮 / 菜单项禁用，不重复弹窗。
- 只有一辆车时：该车必为默认主驾，不展示设为主驾入口。

### 6.9 车辆归档

- 入口：更多菜单「车辆归档」。
- 确认弹窗：琥珀图标（`inventory_2`）、标题「归档「{车名}」？」、正文「归档后，该车辆将从常用车库移出，但过往记账流水与统计数据完整保留，可随时恢复。」
  - 若该车是默认主驾且有其他在库车辆：正文追加「归档后，车库中的「{继任车名}」将成为默认主驾。」继任 = 排序中下一辆；弹窗必须明确写出，不得静默处理。
  - 若该车是唯一在库车辆：正文追加「归档后车库将为空，默认主驾将被清空；历史流水仍保留在账单与统计中。」按钮文案改为「确认归档并清空车库」。
- 操作按钮：「取消」（中性底）/「确认归档」（`secondaryContainer` 底、白字）。
- 成功后：卡片 250ms 收起，列表重排，总览数字与动力构成更新；Toast「已将「{车名}」归档」；归档车辆进入 §6.11 列表。
- 归档后：
  - 该车不再出现在任何车辆选择器（首页、记账、账单、统计、报表、我的页车库）。
  - 历史流水、月度报表、统计仍包含该车数据，并显示归档前的车辆名称 / 车牌快照。
  - 账单 / 统计的车辆筛选中若当前选中该车，清空为「全部车辆」（或切到新主驾）。
- 失败：弹窗保持，显示「归档失败，请重试」，不移动卡片。

### 6.10 删除车辆

删除是不可逆操作，规则必须严于归档：

1. **默认主驾且存在其他在库车辆** → 拦截：
   - 标题「默认主座驾不可直接删除」；正文「「{车名}」当前为默认主座驾。请先将车库中其他座驾设为主驾后再删除。」
   - 按钮只有一个「我知道了，去切换主驾」，点击关闭弹窗并滚动到第一辆普通车辆。
2. **车辆存在任何记账流水（`recordCount > 0`）** → 拦截：
   - 标题「该车辆有历史流水」；正文「「{车名}」名下还有 {n} 笔记账流水。为避免账目缺口，请先归档：归档会保留全部流水且可恢复。」
   - 按钮「取消」/「去归档」；「去归档」关闭本弹窗并打开 §6.9 归档确认。
   - 说明：设计稿的「流水转为未指定车辆或一并清理」语义不明确，P0 不提供级联删除；P1 若产品坚持，需「输入车名确认 + 明确提示删除 N 笔流水」的强确认。
3. **无流水，且非默认主驾 / 或唯一车辆** → 允许删除：
   - 标题「永久删除爱车？」；正文「确定要永久删除「{车名}」吗？删除后车辆档案与配置将无法恢复。」；唯一车辆追加「删除后车库将为空。」
   - 按钮「我再想想」（中性）/「确认删除」（`error` 底、白字）。
4. 成功后：卡片收起；总览更新；Toast「已删除「{车名}」」；该车不再出现在任何选择器；因无流水，账单 / 统计不受影响。
5. 失败：弹窗保持，显示「删除失败，请重试」。
6. 删除按钮视觉始终为 `error`；不可用原因必须解释，不能只置灰不说明。

### 6.11 已归档车辆入口

- 入口：页面底部「已归档车辆」工具卡，仅当 `archived.length > 0` 时显示；左侧 `inventory_2` 图标、标题「已归档车辆」、副文「{n} 辆 · 流水已保留，可随时恢复」、右侧箭头。
- 点击**推入独立页面「已归档车辆」**：封存数量、逐车历史汇总、恢复、查看历史报表与彻底删除都在该页完成，详见[已归档车辆需求](archived-vehicles.md)。
- 本页不再打开归档车辆弹层；归档车辆的写操作统一由归档页承载，避免两套恢复 / 删除入口并存。
- 从归档页返回本页时，归档入口计数与车辆列表使用已失效并刷新的数据。

| 状态 | 表现 |

## 7. 数据口径与格式化

### 7.1 车队汇总

| 指标 | 口径 |
| --- | --- |
| 在库车辆数 | `archivedAt == null` 的车辆数；不含已归档 |
| 累计行驶里程 | 在库车辆 `odometerKm` 之和；各车表显读数，不是「新增行驶里程」 |
| 本月车队总开销 | 当月 1 日 00:00 至下月 1 日 00:00（本地时区）在库车辆全部类别支出之和；退款按负值计入；与账单页「全部车辆」同月合计一致 |
| 动力构成 | ev / phev / hev / ice 分组计数；只显示非零组 |
| 资产健康 | 在库车辆中：保养 `warning` / `overdue`、保险 ≤ 30 天、年检 ≤ 30 天，各计 1 项；`pendingIssueCount` 为去重后的车辆-项目数 |
| 本月产生支出（单车） | 同月该车全部类别支出之和；与首页该车本月开销一致 |

### 7.2 车辆卡指标

| 字段 | 来源 | 缺失处理 |
| --- | --- | --- |
| 当前里程 | `Vehicle.odometerKm` / 最新记账读数 | 必有；0 显示「0 km」 |
| 动力电耗 | `Consumption.primary`（kWh/百公里） | 「—」+「未录入」 |
| 综合油耗 | `Consumption.primary`（L/100km） | 「—」+「未录入」 |
| 亏电油耗（phev） | `Consumption.secondary`（L/100km） | 「—」+「未录入」 |
| 电池健康 SOH | 车辆档案 / 车联字段 `batteryHealthPercent` | 「—」+「未录入」；< 80% 用 `error` |
| 车险剩余 | `insuranceExpiry - today` | 「—」+「未录入」；≤ 30 天用 `error` |
| 保养剩余 | `Maintenance.remainingKm` | 未设置保养周期：不显示提醒 |
| 年检日期 | `inspectionExpiry` | 不显示提醒 |
| 本月支出 | `HomeSummary.monthSpendCents` / 账本聚合 | 无记录显示 ¥0.00 |
| 记账流水数 | 该车全部历史未删除记录数 | 用于删除拦截，不在卡片展示 |

### 7.3 默认主驾与排序

- 默认主驾（`primaryVehicleId`）全库唯一，最多一个；服务端保存。
- 必须满足：若存在在库车辆，则必须有且仅有一个默认主驾；车库为空时允许 `null`。
- 首次添加第一辆车时自动成为默认主驾；添加新车不会自动成为默认主驾。
- 排序：默认主驾置顶；其余按 `sortOrder` 升序；`sortOrder` 在添加时取当前最大值 + 1。
- 归档 / 删除默认主驾后：继任 = 剩余在库车辆中排序最靠前的一辆；无剩余则 `primaryVehicleId = null`，并在确认文案中提前告知（§6.9）。
- 归档 / 删除非默认主驾：不影响主驾。
- 切换主驾不改变 `sortOrder`，只改变置顶展示与默认标记。

### 7.4 归档 / 删除数据规则

| 操作 | 车辆档案 | 历史流水 | 选择器可见 | 可恢复 | 默认主驾 |
| --- | --- | --- | --- | --- | --- |
| 归档 | 保留，标记 `archivedAt` | 完整保留 | 否 | 是 | 若是主驾，按 §7.3 继任 |
| 恢复 | 保留，清空 `archivedAt` | 完整保留 | 是 | — | 无主驾时成为主驾 |
| 删除（无流水） | 永久删除 | 无 | 否 | 否 | 若为唯一车辆，清空主驾 |
| 删除（有流水） | P0 禁止 | — | — | — | — |
| 归档后彻底删除 | 永久删除 | 保留，解除车辆归属 | 否 | 否 | 归档车不是主驾，不涉及 |

- 归档车辆的历史流水、统计、报表继续按 `vehicleId` 归属；展示车辆名称 / 车牌时使用记录快照，不读取归档后的空档案。
- 归档后的彻底删除由[已归档车辆页](archived-vehicles.md)承载：档案销毁、流水保留并解除归属，账单「全部车辆」合计不变；本页只负责归档与拦截，不直接删除有流水车辆。
- 删除车辆不复用「软删除」标记，避免与归档混淆。
- 任何写操作成功后，必须同步失效首页、账单、统计、报表、我的页的车辆与汇总数据（见技术方案 §7.4）。

### 7.5 格式化

| 内容 | 规则 | 示例 |
| --- | --- | --- |
| 里程 | 千分位 + ` km` | `18,426 km` |
| 金额（总览） | `¥` + 千分位，无小数 | `¥1,286` |
| 金额（卡片 / 弹窗） | `¥` + 千分位 + 两位小数 | `¥512.00` |
| 电耗 | 一位小数 + `kWh/百公里` | `14.8` |
| 油耗 | 一位小数 + `L/100km` | `6.8` |
| 百分比 | 整数 + `%` | `98%` |
| 天数 | 整数 + ` 天到期` / ` 天后到期` | `48 天到期` |
| 车辆副标题 | 年款 + 配置 + 动力，单行省略 | `2023款 创世旗舰型 · 纯电` |
| 车牌 | 统一大写、`·` 分隔；无车牌「未填写车牌」 | `粤B·D82K6` |

### 7.6 空值与反常数据

- 金额负值（退款多于支出）：总览显示 `-¥{abs}`，卡片 `-¥{abs}`；不使用红色，避免与错误混淆。
- 里程超过 1,000,000 km：仍显示千分位，数值 `FittedBox` 缩放。
- 同月支出超过 7 位：总览缩放，卡片允许换行单位。
- `recordCount` 与 `monthSpendCents` 缺失：视为 0，不阻塞删除判断（服务端删除接口仍会二次校验）。
- 归档车辆 ID 出现在当前筛选：前端自动回退到全部车辆 / 默认主驾，并 Toast 说明。

- 接口未确认前由 `MockVehicleRepository` 提供本地数据；UI 与 provider 不感知实现。
- 写操作成功但列表刷新失败：保留本地乐观状态，Toast「已保存，列表刷新失败」并提供重试。

## 9. 全局状态与异常

- **单一数据源**：车辆列表、主驾、归档状态只由车辆仓库持有；首页、我的页、账单、统计、记账、报表的车辆选择器读同一份列表。
- **跨页失效矩阵**：设主驾 / 归档 / 恢复 / 删除成功后，失效车库、车辆列表、首页看板 / 记录 / 趋势、账单列表与汇总、统计概览、报表范围、我的页车库；具体见技术方案 §7.4。
- **并发**：同一时刻只允许一个写操作；页面级命令状态串行化；弹窗主按钮 loading 期间不可重复提交。
- **其他端修改**：进入页面下拉刷新获取最新；写操作 409 冲突时刷新并提示，不覆盖服务端。
- **离线**：本页写操作不做离线队列（P1）；离线时按钮可用，提交失败展示网络错误，不产生乐观假成功。
- **空车库**：允许存在；首页、记账、统计、账单、报表显示各自空态；不能因此崩溃或反复请求。
- **删除 / 归档当前选中车辆**：自动回退到新主驾或「全部车辆」；详见 §7.4。
- **登录 / 多账号**：当前无账号体系；接入后车辆归属账号，切换账号需清空本地车库缓存。

## 10. 非功能需求

| 项 | 要求 |
| --- | --- |
| 性能 | 首屏 ≤ 1s（Mock）；下拉刷新 ≤ 800ms；设主驾 / 归档 / 恢复 ≤ 300ms；删除 ≤ 300ms；卡片操作 60fps |
| 可用性 | 所有写操作有确认或明确后果；不可用操作有原因说明；空态有下一步 |

| 深色模式 | 复用 `AppPalette.dark` / `AppTokens.dark`；Hero 渐变在深色下降低亮度 10%，文字保持白色对比 ≥ 4.5:1 |

| 隐私 | 不在日志中打印车牌、车辆 ID 关联的个人信息；分享 / 导出默认隐藏车牌 |
| 兼容 | Android arm64 优先、iOS；最小宽度 320；不引入新依赖 |
| 稳定性 | 车库为空、全量归档、重复点击、快速返回均不崩溃；写操作失败可重试 |
