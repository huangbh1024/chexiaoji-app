## 1. 背景与目标

账单页回答「花了多少、花在哪」，详情页回答「这一笔是什么」。但要把数据记进账本，用户需要的是一个**足够快、又不丢失细节**的录入页：

- 站在充电桩旁，30 秒内记完一笔充电，同时顺手补上电量与里程；
- 加完油，用「加满」快捷金额，选 95#，系统自动算出升数；
- 停车出场，按 8 元/小时记一笔，顺手拍张发票；
- 保养后补录，填门店、里程与项目，方便下次提醒；
- 从某笔记录点「再记一笔」，车辆、分类、地点都能沿用。

设计目标：

1. **快**：金额 → 分类 → 保存，三步可完成；常用字段有合理默认值，不强迫每次全填。
2. **准**：金额、单价、数量、里程之间互相推导且只有一个主输入，避免出现「100 元却充了 83 度电」这类对不上的账。
3. **懂车**：车辆切换、动力类型默认分类、油品标号、SOC、里程读数都按车的实际情况给默认值。
4. **不易丢**：任何输入都有本地状态；误触关闭、保存失败、切后台都不会丢掉已填内容。

## 2. 用户与典型场景

| 角色 | 场景 | 页面要求 |
| --- | --- | --- |
| 纯电车主 | 公共快充站补能，想知道这次充了多少度、每公里多少钱 | 金额 + 充电参数 + 里程 → 自动算 kWh、SOC 与 ¥/km |
| 燃油车主 | 加油后录入，习惯按「加满」或固定金额记 | 加注升数自动算；92/95/98 单选；「加满」按钮 |
| 插混车主 | 有时充电、有时加油，两套参数都要顺手 | 切换分类即换参数卡，车辆默认分类为充电 |
| 多车家庭 | 用另一辆车产生开销 | 车辆卡切换，车牌 / 动力 / 里程同步；可沿用上次分类 |
| 记账习惯用户 | 每次停车、过路费、洗车都要记 | 分类卡直接切换，非补能分类不强迫填里程 |
| 补录用户 | 晚上补录白天的保养 | 发生时间可改，里程基线按发生时间回溯，不出现负里程 |

## 3. 范围

### 3.1 本期包含（P0）

- 顶部栏：关闭、标题「记一笔开销」、OCR 入口（占位）。
- 当前车辆卡 + 车辆切换浮层（含动力类型徽标、车牌、当前里程）。
- 7 个支出分类的横向胶囊选择，选中态与分类参数联动。
- 金额输入卡：大字号输入、清空、快捷金额、能耗预估条。
- 分类明细参数卡：充电 / 加油 / 停车 / 过路费 / 保养维修 / 洗车美容 / 车险车税。
- 里程仪表卡：上次读数、本次读数、区间里程。
- 发生时间、地点、支付账户三行。
- 备注与凭证卡：备注、最多 4 张凭证照片。
- 底部固定「保存并记入账本」。
- 创建模式与编辑模式（同一页面，预填不同）。
- 关闭前未保存确认；保存成功后的全局数据刷新。
- 明暗主题、无障碍、键盘避让。

### 3.2 本期不做（P1 / P2）

- OCR 识别、发票确认浮层、自动填单。
- 语音记账、快捷指令、桌面小组件。
- 周期性开销（保险、月租车位）自动生成。
- 多笔连续录入（保存后不退出、清空表单继续记）。
- 离线排队提交与跨设备草稿同步。
- 负金额 / 退款录入（P1 从详情页标记退款）。
- 预算、分摊、家庭成员记账。

### 3.3 设计稿未覆盖的内容

| 缺口 | 本期处理 |
| --- | --- |
| 三个非补能分类的参数卡 | 按 §6.6 的建议稿补齐最小字段 |
| 时间 / 地点 / 支付选择浮层 | 复用 BottomSheet 与现有表单样式，交互按 §6.8 |

### 4.5 适配

- 竖屏，内容区最大宽度 448px 居中；左右安全区。
- 覆盖 375–430pt；小屏（≤ 375）金额字号降为 32，分类胶囊允许横滑。
- 顶部栏吸顶，高度 56 + 状态栏；底部栏固定，高度 68 + 底部安全区。
- 键盘弹起时：底栏贴键盘上沿；内容区底部内边距 = 底栏高度 + 键盘 + 16，保证可滚到备注与凭证。
- 内容区底部始终预留 24 + 底栏高度，避免最后一张卡被遮挡。
- 明暗两套主题；深色按首页 `AppPalette.dark` 推导，分类语义色不变。

- 不允许未来时间：日期选择器最大值为今天，时间晚于当前时保存时拦截并提示「发生时间不能晚于现在」。
- 允许补录，最早 2000-01-01；超过 10 年前的补录在保存前提示一次。
- 展示格式：今天 `今天 HH:mm`；昨天 `昨天 HH:mm`；今年其他日期 `M月D日 HH:mm`；跨年 `YYYY年M月D日 HH:mm`。

**地点**

- 输入浮层：标题「服务网点 / 地点」，单行输入 ≤ 30 字，右「完成」；下方「最近地点」最多 3 个胶囊（来自默认值接口）。

### 7.2 推导公式

金额全链路使用整数分；数量、单价展示值由分换算。

| 指标 | 公式 | 边界 |
| --- | --- | --- |
| 充电电量 kWh | `amountCents / unitPriceCentsPerKwh` | 单价 ≤ 0 → 不显示；结果保留 2 位 |
| 加油升数 L | `amountCents / unitPriceCentsPerLiter` | 单价 ≤ 0 → 不显示；保留 2 位 |
| 结束 SOC | `min(100, socStart + kwh / batteryCapacityKwh × 100)` | 电池容量 ≤ 0 → 隐藏 SOC；四舍五入取整 |
| 停车时长 | `amountCents / rateCentsPerHour` | 费率 ≤ 0 → 「—」；保留 1 位小时 |
| 每公里成本 | `amountCents / distanceKm` | 里程为空 / 0 → 隐藏；保留 2 位 |
| 区间里程 | `odometerKm − lastOdometerKm` | 任一为空 → 「—」；小于 0 → 校验错误 |
| 充满金额 | `batteryCapacityKwh × (100 − socStart) / 100 × unitPrice` | 容量未知 → 隐藏按钮 |
| 加满金额 | `tankCapacityL × unitPrice` | 油箱容量未知 → 隐藏按钮 |
| 金额解析 | `round(输入元 × 100)` | 超过 2 位小数不接受；上限 99,999,999 分 |

| 充电单价 | 0.10–20.00 | 请输入 0.10–20.00 的单价 |

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 金额输入 | 无千分位，最多 2 位小数；失焦补齐 | `100.00`、`0.50` |

### 7.5 时间口径

- 使用设备本地时区；发生时间默认取进入页面时的当前时间，精确到分钟，秒固定为 00。
- 「今天 / 昨天」在页面重新进入或时间选择浮层打开时重算。
- 里程基线按发生时间回溯，而不是按「当前最近一笔」；补录历史不会让里程倒挂。
- 保存时服务端按同一时区写入 ISO 8601；跨时区旅行时以设备本地时区为准，不做自动换算。

### 8.2 里程基线

```
GET /api/v1/vehicles/{vehicleId}/odometer?before=2026-11-15T08:42:00%2B08:00&excludeRecordId=rec_123
→ {
    "lastReadingKm": 18375,
    "recordedAt": "2026-11-14T18:20:00+08:00",
    "recordId": "rec_122",
    "currentOdometerKm": 42150
  }
```

- `before` 为当前选择的发生时间；`excludeRecordId` 仅编辑模式传入。
- 无历史读数时返回 `lastReadingKm: null`，`currentOdometerKm` 仍返回车辆资料里程。
- 该接口需支持补录场景：`before` 早于全部记录时返回 null，而不是最近一笔。


- 服务端按 `category` 校验 `detail.type` 必须一致，不一致返回 422。
- `lastOdometerKm` 由客户端回传，用于服务端二次校验；服务端以自身基线为准，冲突时返回 409 `ODOMETER_CONFLICT` 并附正确基线。
- 创建成功返回完整记录，客户端不必再拉详情。

### 8.4 编辑

```
PATCH /api/v1/expenses/{id}
If-Match: "2026-11-14T20:10:00.000Z"

{ "...": "与创建同构，可只传变更字段" }
→ 200 { "id": "rec_124", "record": { "...": "…" }, "updatedAt": "2026-11-15T09:00:00+08:00" }
```

- 编辑模式允许修改车辆、分类、金额、时间、里程、全部参数与备注凭证。
- 使用 `If-Match` / `version` 做乐观并发；不一致返回 409 与最新记录，由客户端提示重新载入或覆盖。
- 分类切换会整组替换 `detail`，不保留旧分类字段。

### 8.5 凭证上传

```
POST /api/v1/uploads/receipts
Content-Type: multipart/form-data
file=@receipt.jpg

→ 201 { "id": "rcpt_01", "url": "https://...", "width": 1600, "height": 1200 }
```

- 单张 ≤ 5MB；一次最多 4 张，可按张上传，保存时只提交 `receiptIds`。
- 未提交到任何记录的凭证由服务端定期清理（建议 24 小时）。
- 客户端不缓存远端 URL 到日志；缩略图使用本地文件。

### 8.6 错误约定

| HTTP / 业务码 | 场景 | 客户端处理 |
| --- | --- | --- |
| 400 `INVALID_AMOUNT` | 金额非法 | 定位金额字段并提示 |
| 404 `VEHICLE_NOT_FOUND` | 车辆已删除 | Toast「车辆已不存在」，回到车辆选择 |
| 409 `ODOMETER_CONFLICT` | 里程基线过期 | 提示「里程读数已更新」，刷新基线后重试 |
| 409 `RECORD_CONFLICT` | 编辑并发 | 弹重新载入 / 覆盖 |
| 413 `RECEIPT_TOO_LARGE` | 凭证过大 | 提示单张不超过 5MB |
| 422 `DETAIL_MISMATCH` | 分类与参数不匹配 | Toast「参数与分类不一致」，保留输入 |
| 5xx / 超时 | 服务异常 | 保留输入 + 重试 |

## 9. 全局状态与异常

| 状态 | 表现 |
| --- | --- |
| 路由进入 | 全屏推入，底部 Tab 隐藏；关闭后回到来源页并保留其滚动位置 |
| 默认值请求中 | 车辆卡、快捷金额骨架；金额与分类可操作 |
| 默认值失败 | 本地兜底值 + Toast；不阻塞录入 |
| 无车辆 | 空态替换表单；关闭可用；「去添加」暂以 Toast 占位 |
| 车辆被删除 | 保存时 404 → Toast 并回到车辆选择，输入保留 |
| 里程基线失败 | 不阻塞保存，但区间行显示重试；保存时提示「本次不校验里程」 |
| 分类切换 | 参数卡替换；旧分类专属值清空；金额与通用字段保留 |
| 金额为 0 或空 | 保存禁用；预估条隐藏或显示 0 值但不计算 |
| 凭证超限 | 第 5 张被拒绝并提示「最多上传 4 张」 |
| 权限被拒 | 提示设置路径；不产生空白缩略图 |
| 保存中 | 按钮转圈；关闭拦截；重复点击无效 |
| 保存失败 | 表单与焦点保留；按钮恢复；Toast |
| 保存冲突 | 编辑模式弹选择；创建模式按幂等键重试，不重复入账 |
| 离线 | 保存提示网络不可用；输入保留；P1 草稿队列 |
| 极长文本 | 车辆名、地点、卡头提示均单行省略；备注按 200 字截断 |
| 文本放大 | 1.3 倍下卡片高度自适应，金额不截断，底栏文字不换行 |
| 主题切换 | 输入内容、焦点、滚动位置保留 |

## 10. 非功能需求

- **性能**：路由推入到可交互 ≤ 500ms；金额 / 参数变化到预估条更新 ≤ 100ms；保存请求 P90 ≤ 1.5s；输入延迟 ≤ 50ms；滚动 60fps。
- **内存**：凭证缩略图按显示尺寸解码（`cacheWidth`），压缩后原图不常驻；同时最多 4 张。
- **稳定性**：旋转、切后台、来电中断后已填内容不丢；保存具备幂等性；上传失败可单独重试。
- **主题**：浅色 + 深色全量适配；输入框、错误态、骨架、遮罩在深色下对比度 ≥ 3:1，正文 ≥ 4.5:1。
- **无障碍**：所有图标按钮有语义标签；金额、里程、单价不仅依赖颜色区分；错误用 `Semantics(liveRegion: true)` 播报；点击区 ≥ 44；分类胶囊朗读选中态。
- **隐私**：车牌、地点、保单号、凭证照片不进日志与埋点明文；凭证在应用私有目录临时保存，保存成功或放弃后清理；保单号展示脱敏。
- **本地化**：本期仅中文、人民币、公里、kWh、L；所有文案集中管理，不在 Widget 内硬编码。
- **兼容性**：Android 8+ / iOS 13+；数字键盘、日期选择器、相机与相册权限文案分别配置；最大内容宽 448。
