## 1. 背景与目标

「归档」是车小记处理**不再使用但仍需保留历史**的车辆的方式：车辆从首页看板、快捷记账与统计选择器中消失，流水、报表与凭证完整保留。车辆管理页已经提供归档与恢复，但恢复入口只是一个轻量底部弹层，无法承载：

- 每辆车封存了多久、封存时里程多少、累计花了多少钱、历史能耗多少；
- 恢复前的后果说明（车库为空时恢复会成为主驾）；
- 对归档车辆的**彻底清理**——用户在卖车、过户或不再需要该车数据时，需要一个明确、不可误触的销毁入口。

本页要在一屏内回答四个问题：

1. 我**封存了哪些车**，各自封存多久、历史体量多大？
2. 归档后**哪些数据还在**，恢复后会回到哪里？
3. 怎么**恢复**一辆车，恢复后会发生什么？
4. 怎么**彻底清理**一辆车，删掉之后账单和报表会怎样？

设计目标：

- 每辆归档车的「封存时长 + 里程 + 累计花费 + 历史能耗」在卡片内一眼可见。
- 恢复 1 次确认完成；恢复后立即回到车库并联动首页 / 记账 / 统计。
- 彻底删除必须依次经过「打开危险弹层 → 输入车牌尾号 → 勾选知情 → 点击销毁」，不允许一次点击完成。
- 删除后果用**逐条清单 + 真实数字**说明，不使用恐吓性动效（不做脉冲闪烁）。

## 2. 用户与典型场景

| 用户 | 场景 | 关注点 |
| --- | --- | --- |
| 换车用户 | 买了新车，旧车归档 | 旧车历史还在不在，能不能随时恢复 |
| 卖车用户 | 车辆已售出，归档保留历史 | 封存时长、累计花费、历史报表可查 |
| 误归档用户 | 手滑归档了仍在用的车 | 怎么最快恢复，恢复后主驾是谁 |
| 数据洁癖用户 | 不再需要旧车数据 | 彻底删除会删什么、账单会不会断 |
| 多车家庭 | 多辆车轮换使用 | 归档列表按时间排序，能快速定位 |

典型场景：

- **归档三个月后回看**：打开本页，看到「封存 92 天 · 52,380 km · ¥9,640 · 13.6 kWh」，确认历史完整。
- **重新启用旧车**：点「恢复至车库」，弹窗说明后确认，回到车辆管理页末尾，首页与记账默认车辆可再次选择它。
- **卖车后清理**：打开「彻底删除」，看到「该车名下 38 笔记账、合计 ¥9,640 将继续保留在账单与报表中，但不再归属任何车辆」，输入尾号 `D82K6` 并勾选后销毁档案。
- **误归档**：进入本页直接恢复，不需要先找设置或联系客服。

### 3.2 本期不做

- 云端备份、多端恢复、账号级回收站（当前无账号体系）。
- 车辆过户、报废、保险退保等交易或服务闭环。
- 把归档车辆的历史流水迁移到另一辆车。
- 归档车辆的编辑、记一笔、能耗统计入口（归档车辆不参与日常记账，恢复后可用）。
- 归档车辆的保养 / 保险 / 年检提醒。
- 平板 / 桌面双栏与横屏专属布局。

### 3.3 设计脚本残留（本期处理）

| 设计稿表现 | 处理 |
| --- | --- |
| 底部导航与中央 FAB | 本页是二级页，由 `Navigator` 推入，不渲染底部导航；返回即回车辆管理 |
| 顶部栏右上角「搜索」「说明 / 筛选」图标 | P0 归档数量通常 ≤ 5，搜索筛选无收益；**不渲染**，P1 再随列表规模补 |
| 说明卡徽标「云端完整备份」 | 当前无云端备份，**改为「历史完整保留」**，不承诺云能力 |
| 删除弹层「无法通过云端多端同步恢复」 | **改为「删除后无法恢复，重新添加需重新录入车辆参数。」** 不提云同步 |
| 卡片元信息「归档于 … · 原因：置换新车」 | 当前无归档原因字段，P0 **只展示归档日期**；P1 在归档弹窗采集原因后再展示 |
| 列表标题右侧「支持按年份与里程调阅」 | P0 无筛选，改为**「按归档时间倒序」**，避免展示不可用能力 |
| 「彻底删除」调用系统 `confirm()` | 改为独立危险弹层（§6.7），不使用原生确认框，也不叠加二次系统弹窗 |
| 危险按钮 `animate-pulse` 脉冲 | **不实现**；确认条件满足后一次性变为实心危险色，避免动效诱导 |
| 恢复弹层正文「您可以随时在车库中切换为主力座驾」 | 保留；补充「当前车库无在用车辆时，恢复后自动成为默认主驾」 |
| 设计稿一键恢复（无确认） | 本页统一走确认弹层（§6.5），与危险操作保持一致的审慎度 |
| 演示数字 2 辆 / 52,380 km / ¥9,640 / 38 笔 | 不写死，按真实数据计算；Mock 种子保持 4 辆在库，归档车辆通过归档操作产生 |

- 基准画布 390 × 844（设计稿 780 × 2104 / 780 × 1768 @2x）。

- 系统字号放大到 1.3 倍：卡片自然增高；三列指标允许标签两行，数值不截断。

### 6.1 顶部栏

- 左侧 40 × 40 圆形返回按钮（`arrow_back`，`surface` 底、轻阴影），点击返回车辆管理页；写操作进行中允许返回（本页不承载未保存表单）。
- 标题「已归档车辆」，`headlineMd`。
- 副标题「共 {n} 辆封存座驾 · 历史流水安全保留」：
  - `n` 为当前归档车辆数，数字用主色 600 字重；
  - 加载中显示「正在读取封存档案…」；
  - 失败显示「档案读取失败，点击重试」；
  - `n = 0` 时显示「暂无封存座驾」。
- 右侧无图标（P0 不渲染搜索 / 筛选；P1 再补）。
- 吸顶 + 毛玻璃背景，滚动时内容从下方穿过。

### 6.2 档案封存机制说明卡

- 渐变底（`surfaceContainerLowest → surfaceContainerLow → surfaceContainer`），圆角 26，内边距 20，白色 80% 描边，柔和阴影；背景两个低透明度圆形光斑仅作装饰，不拦截点击。
- 左侧 44 × 44 图标底盘（`inventory_2`，主色）；右侧：
  - 标题「档案封存机制」+ 徽标「历史完整保留」（主色 10% 底、主色文字）。
  - 正文「已归档的车辆不会出现在首页仪表盘与快捷记账列表中，但其所有历史记账凭证、能耗曲线及报表均完整保留，可随时恢复回车库。」
- 说明卡不提供操作；P1 若增加「备份说明」入口再改为可点击。

### 6.3 封存座驾列表标题

- 左侧 4 × 16 主色竖条 + 「封存座驾列表」+ 8 直径主色圆点。
- 右侧「按归档时间倒序」，`labelMd`、`outline`。
- 列表为空时不显示该标题区（由空态接管）。

### 6.4 归档车辆卡

#### 6.4.1 结构

| 区域 | 内容 |
| --- | --- |
| 头部 | 动力图标底盘（48 × 48，圆角 16，动力色 14% 底）+ 车名（`headlineSm`）+ 配置徽标（`specLabel`，`surfaceContainer` 底）+ 车牌胶囊（等宽字体）+ 动力色圆点 + 动力文案 + 右侧封存徽标 |
| 三指标托盘 | 三列等宽，中间列有 1px 左分隔线；标签 `labelSm`，数值 `headlineSm`，单位 11 号常规 |
| 归档元信息 | `event_note` 14 号图标 + 「归档于 {yyyy年M月d日}」；P0 不展示归档原因 |
| 操作行 | 顶部 1px 分隔线；左侧「彻底删除」（`outline` 文字 + `delete_outline` 图标，按压态 `error`）；右侧「查看历史报表」（`surfaceContainer` 胶囊）与「恢复至车库」（主色胶囊、`onPrimaryContainer` 文字） |
| 背景装饰 | 右上角动力色 15% → 透明的径向渐变，不遮挡文字，不参与点击 |

#### 6.4.2 三指标

| 槽位 | 标签 | 取值 | 单位 | 颜色 |
| --- | --- | --- | --- | --- |
| 1 | 封存总里程 | 归档时表显里程，千分位 | km | `onSurface` |
| 2 | 累计记账花费 | 该车全部未删除流水合计，整数元 | ¥ | `onSurface` |
| 3 | 历史平均电耗（EV / PHEV）或 历史综合油耗（HEV / ICE） | 数值保留 1 位小数 | kWh/百公里 或 L/100km | 动力色 |

- 缺失数据（无能耗读数、无流水）显示「—」，单位显示「未录入」或直接隐藏；**不得填 0 或伪造演示值**。
- 累计花费为 0 时显示 `¥0`，不显示「—」（有明确语义：该车无流水）。
- 三列在 1.3 倍字号下允许标签换行，数值与单位保持同行。

#### 6.4.3 操作行

- **恢复至车库**：主按钮，点击打开恢复确认弹层（§6.5）。
- **查看历史报表**：副按钮，点击打开该车最近一次记账月份的月度报表（§6.6）；无任何流水时按钮置灰，点击 Toast「该车辆暂无历史流水」。
- **彻底删除**：危险文字按钮，点击打开危险弹层（§6.7）；不要求先恢复，归档车辆随时可执行。
- 任一写操作进行中，本卡三个按钮均禁用（60% 透明度），不重复提交。
- 触控区不小于 44 × 44；按钮间距 ≥ 8。

### 6.5 恢复至车库

- 点击「恢复至车库」打开底部确认弹层：
  - 图标 56 × 56、圆角 18、主色 15% 底；`unarchive` 图标。
  - 标题「将「{车名}」恢复至车库？」
  - 正文「恢复后，该车辆将重新出现在车辆管理、首页仪表盘及快捷记账列表中，可随时在车库中切换为主力座驾。」
  - 若当前车库无在用车辆，追加「当前车库没有在用车辆，恢复后该车将成为默认主驾。」
  - 按钮：「取消」（中性底）/「确认恢复」（主色底、白字）。
- 成功后：
  - 弹层关闭，卡片 250ms 收起，列表计数 `n - 1`；
  - Toast「已成功将「{车名}」恢复至常用车库」；
  - 若恢复后车库原本为空，主驾自动设为该车，首页 / 记账 / 统计立即可用；
  - 恢复的车辆排在车辆管理页末尾（`sortOrder = max + 1`）。
- 失败：弹层保持，显示「恢复失败，请重试」，按钮恢复可点；不移动卡片、不改计数。
- 恢复不改变历史流水归属，不需要二次输入。
- 弹层不支持下滑 / 点击遮罩关闭；提交中禁止系统返回，避免命令已完成但弹层被提前关闭。

### 6.6 查看历史报表

- 点击后打开月度报表页，范围固定为该车**最近一次记账所在月份** + 该车 `vehicleId`。
- 报表页顶部车辆筛选展示「{车名}（已归档）」，允许用户切换月份；车辆选择器可切回其他在用车辆或「全部车辆」。
- 该车无流水时按钮禁用（§6.4.3），不打开空报表。
- 报表页返回本页，不改变列表状态。
- 报表口径与账单一致：只聚合未删除流水；归档 / 彻底删除不修改历史报表的金额与笔数。
- P1：在本页直接导出该车历史账单 / 报表。

### 6.7 彻底删除

#### 6.7.1 入口与前置条件

- 入口：归档卡片左下「彻底删除」。
- 仅归档车辆可彻底删除；在用车辆仍按[车辆管理需求 §6.10](vehicle-management.md)的「删除 / 归档」规则处理。
- 点击后先打开危险弹层，不立即执行任何写操作。

#### 6.7.2 弹层结构

从上到下：

1. 顶部拖拽把手（48 × 4，`outlineVariant`），内容可滚动，最大高度 92%。
2. 危险图标区：56 × 56、圆角 20、`errorSoft` 底 + `delete_forever` 实心图标 + 右上角 12 直径红点。
3. 标题「彻底删除车辆档案？」+ 危险胶囊「不可撤销的高风险清除操作」（`errorSoft` 底、`error` 文字、`warning` 图标）。
4. 目标车辆识别卡（`surfaceContainerLow` 底、圆角 16）：
   - 车名 + 配置（如「特斯拉 Model 3 2021款」）；
   - 车牌胶囊 + 动力文案；
   - 右侧「封存状态」+「封存 {n} 天」；
   - 底行「历史总里程」+ 表显里程。
5. 影响清单（`errorSoft` 40% 底、圆角 16、`error` 100 20% 描边）：
   - 清单标题「删除影响清单」（`report` 图标 + 危险色 700）。
   - **历史账单解除车辆归属**：该车名下 {n} 笔记账、合计 {金额}，将继续保留在账单与报表中，但不再归属任何车辆。若 `n = 0`，显示「该车暂无记账流水，账单不受影响。」
   - **能耗档案清空且不可复原**：该车的百公里能耗曲线、按车统计与电池健康分析将不再可查看；已导出的报表文件与账单总额不受影响。
   - **不可逆销毁**：删除后无法恢复，重新添加需重新录入车辆参数。
   - 金额与笔数必须来自真实数据，不得使用演示数字。
6. 双因子确认区：
   - 车牌尾号输入：标签「输入车牌尾号确认删除」，右侧等宽危险色显示期望尾号（如 `5K888`）；输入框等宽字体、居中偏左、最大 5 字符、自动转大写、过滤空格与「·」；匹配时右侧显示主色 `check_circle`。
   - 知情勾选：「我已了解该车辆档案将被永久删除，历史流水将失去车辆归属。」（`bodySm`，不小于 44 高触控区）。
7. 操作按钮（纵向排列，等宽）：
   - 上一行「暂不删除，保留归档」：`surfaceContainer` 底、`shield` 图标、`headlineSm` 粗体，作为视觉优先的安全出口；
   - 下一行「彻底销毁座驾档案」：实心危险色、`delete_sweep` 图标；未满足双因子时 40% 透明度并禁用。

#### 6.7.3 双因子确认规则

| 条件 | 规则 |
| --- | --- |
| 期望尾号 | 车牌去掉空格与「·」后取**最后 5 位**；不足 5 位时取全部 |
| 输入匹配 | 去首尾空格、转大写后与期望尾号完全相等；支持字母与数字 |
| 勾选 | 复选框必须为选中状态 |
| 解锁 | 输入匹配 **且** 勾选，两者缺一不可；按钮从 40% 透明度变为实心危险色 |
| 取消 | 通过「暂不删除，保留归档」关闭弹层，无任何变更；输入内容不保存。弹层不支持下滑 / 遮罩关闭 |
| 重复提交 | 提交中按钮显示 loading 并禁用；输入框与勾选保持可见但不可编辑；系统返回被拦截 |
| 额外确认 | **不再叠加系统 `confirm()`**；本弹层即最终确认 |

#### 6.7.4 删除结果

- 成功后：
  - 弹层关闭，卡片 250ms 收起，列表计数 `n - 1`；若 `n = 0` 显示空态；
  - Toast「已彻底删除「{车名}」的车辆档案」；
  - 车辆管理页、首页、记账、统计、账单、我的页、月度报表全部失效并刷新；
  - 该车历史流水保留，账单「全部车辆」合计不变；按车筛选不再提供该车（§7.5）。
- 失败：
  - 弹层保持，显示「删除失败，请重试」；尾号不匹配显示「车牌尾号不匹配，请重新输入」；
  - 输入与勾选保留，按钮恢复可点；
  - 不移动卡片、不改计数。
- 并发：车辆已被其他端删除时，关闭弹层并 Toast「该车辆已不存在，列表已刷新」。

## 7. 数据口径与格式化

### 7.1 封存时长

- `n = max(0, today - archivedAt 的天数)`（按本地日期差，不含时分秒）。
- `n = 0` 显示「今日封存」；`n ≥ 1` 显示「封存 {n} 天」。
- 时钟回拨或 `archivedAt` 为空时按 0 处理，不显示负数。

### 7.2 封存总里程

- 取归档时车辆的**表显里程**（`Vehicle.odometerKm`），归档后不再更新。
- 千分位显示，单位 `km`；缺失显示「—」。

### 7.3 累计记账花费

- 该车全部**未删除**流水的金额合计，含全部类别；退款按负数计入。
- Mock 账单只生成近 24 个月数据，因此 Mock 口径为「近 24 个月」；生产接口返回全生命周期合计。
- 展示为整数元（四舍五入），千分位，如 `¥9,640`；为 0 时显示 `¥0`。
- 与账单「全部车辆」月合计不冲突：本指标是单车全历史，不做月度拆分。

### 7.4 历史平均能耗

- EV / PHEV：`历史平均电耗`，取归档前最后一次有效能耗读数（`kWh/百公里`）。
- HEV / ICE：`历史综合油耗`，取归档前最后一次有效能耗读数（`L/100km`）。
- 归档后不重新计算；Mock 使用该车 dashboard 的 `consumption.primary`，生产由归档列表接口返回冻结值。
- 无读数显示「— / 未录入」，不计算、不补默认值。

### 7.5 彻底删除的数据规则

**建议语义（Q1）：销毁车辆档案 + 历史流水解除车辆归属，而不是级联删除流水。** 理由：

1. 设计稿清单明确写「历史账单解除关联……将永久解除车辆归属」，不是「删除账单」；
2. 现有产品规则是「为避免账目缺口，请先归档」，账目完整性优先；
3. 财务凭证与已导出报表不应因删除车辆而失真。

| 对象 | 归档 | 恢复 | 彻底删除 |
| --- | --- | --- | --- |
| 车辆档案（基础信息、配置、SOH、保险 / 年检） | 保留 | 保留 | **删除** |
| 归档记录 `archivedAt` | 写入 | 清空 | 随档案删除 |
| 历史流水（金额、时间、分类、备注、车辆名称快照） | 完整保留 | 完整保留 | **保留**，解除车辆归属 |
| 账单「全部车辆」合计 | 不变 | 不变 | **不变** |
| 账单 / 统计按车筛选 | 不提供该车选项 | 恢复可选 | 不再提供该车 |
| 月度报表（历史月） | 可按该车查看 | 可查看 | 仅「全部车辆」口径可查看；该车范围入口不再提供 |
| 首页 / 记账 / 统计车辆选择器 | 不可见 | 可见（末尾） | 不可见 |
| 默认主驾 | 由继任车辆接管 | 无主驾时成为主驾 | 不涉及（归档车不可能是主驾） |
| 单笔详情车辆卡 | 展示快照 | 展示快照 | 展示快照，徽标「已解绑」，无跳转箭头 |
| 已导出的 PDF / CSV / 长图文件 | 保留 | 保留 | 保留（本地文件不回收） |

补充规则：

- 流水的车辆归属字段保留原 id 作为历史痕迹，但不再对应任何可操作车辆；所有展示使用记录内的车辆名称 / 车牌快照。
- 彻底删除不修改账单总额、分类构成与统计大盘；只影响「按车」维度。
- 车辆删除后重新添加同名车辆视为新档案，不继承历史流水。
- 若产品最终选择「级联删除流水」（Q1），必须同步修改 §6.7 文案、账单 / 统计 / 报表口径与验收项，不在本版默认。

### 7.6 格式化

| 内容 | 规则 | 示例 |
| --- | --- | --- |
| 里程 | 千分位 + `km` | `52,380 km` |
| 金额 | 整数元 + 千分位 | `¥9,640` |
| 金额（弹层清单） | 整数元 + 千分位 | `¥9,640` |
| 能耗 | 1 位小数 + 单位 | `13.6 kWh/百公里`、`6.5 L/100km` |
| 归档日期 | `yyyy年M月d日` | `2024年8月15日` |
| 封存时长 | `封存 {n} 天` / `今日封存` | `封存 42 天` |
| 笔数 | 千分位 + `笔` | `38 笔` |
| 车牌 | 原样展示，等宽字体 | `粤B·5K888` |

### 7.7 空值与反常数据

- `archivedAt` 缺失：按「今日封存」处理，仍允许恢复与删除。
- 车牌为空或不足 5 位：删除确认改用**完整车牌**匹配；车牌也为空时改用输入车名末 4 字（Q7），并在弹层说明。
- 能耗读数缺失：显示「— / 未录入」。
- 流水统计数据加载失败：三指标中「累计记账花费」与「历史平均能耗」显示「—」，其余信息正常展示，卡片仍可恢复 / 删除。
- 归档列表数量与车辆管理入口计数不一致时，以本页接口结果为准，并在刷新后修正入口计数。

### 8.3 错误码

| HTTP | code | 场景 | 前端处理 |
| --- | --- | --- | --- |
| 409 | `VEHICLE_NOT_ARCHIVED` | 车辆已恢复，不能再按归档车删除 | 关闭弹层、刷新列表、Toast「该车辆已恢复，请在车库中操作」 |
| 404 | `VEHICLE_NOT_FOUND` | 已被其他端删除 | 关闭弹层、刷新列表、Toast「该车辆已不存在」 |
| 400 | `PLATE_TAIL_MISMATCH` | 尾号不匹配（服务端二次校验） | 弹层内「车牌尾号不匹配，请重新输入」 |
| 409 | `VEHICLE_DELETE_CONFLICT` | 并发写 / 车辆状态变化 | 刷新后重试 |
| 500 | `INTERNAL` | 其他 | 弹层内「删除失败，请重试」 |

### 8.4 客户端容错

- `GET /garage/archived` 失败时保留上次快照；无快照显示错误态与重试。
- 恢复接口幂等：重复恢复返回当前状态；客户端成功后以刷新结果为准。
- 彻底删除接口成功后不再请求车辆详情；列表移除该车。
- 车牌尾号在客户端先校验，服务端必须再次校验；客户端校验不得作为唯一安全边界。
- 接口未确认前由 `MockVehicleRepository` 提供本地数据，UI 与 provider 不感知实现。

## 9. 全局状态与异常

- **单一数据源**：归档车辆、在库车辆、默认主驾仍由车辆仓库 / `VehicleStore` 持有；本页不维护第二份车辆数组。
- **跨页失效**：恢复 / 彻底删除成功后，失效归档列表、车库、车辆列表、首页看板与记录、账单列表与汇总、统计概览、我的页车库、月度报表。
- **作用域归一化**：删除车辆的 id 若残留在账单 / 统计筛选、我的页车库范围中，统一回退到主驾或「全部车辆」；本页不提供该车入口。
- **并发**：同一时刻只允许一个恢复 / 删除；弹层按钮 loading 期间不可重复提交。
- **返回**：写操作进行中允许返回，后台命令继续完成并 Toast；返回后车辆管理页刷新。
- **离线**：不做离线队列；提交失败展示网络错误，不产生乐观假成功。
- **空归档**：允许存在；入口在数量为 0 时隐藏，但页面仍可因恢复最后一辆车而停留在空态。
- **登录 / 多账号**：当前无账号体系；接入后归档车辆归属账号，切换账号需清空本地缓存。
