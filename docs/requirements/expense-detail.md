## 1. 背景与目标

账单页回答「每一笔都记了什么」，但一条记录的完整信息——支付渠道与尾号、精确时间、商户全称、所属车辆与里程、能耗 / 单价指标、对比、票据、位置——在列表卡片里放不下。当前点击记录卡只弹「账单详情待接入」，用户无法核对、补充或清理一笔开销。

当前版设计把这件事收成**一个通用页面**：不再按分类拆页面，而是用同一套结构承载 6 类开销，分类差异由后端数据驱动。用户进入后应能：

1. 确认这笔钱花在哪、什么时候、用什么付的、记在哪辆车上；
2. 看懂这笔开销的关键指标（单价、电量 / 升数、里程、时长等）与对比结论；
3. 补备注、加标签、查看票据、导航到网点；
4. 分享、复制或删除这笔记录。

设计目标：

- **一眼确认金额**：摘要卡以金额为中心，标题、分类徽标、状态、时间围绕金额排布。
- **通用而不雷同**：6 类开销共用结构，只换图标、徽标、指标、对比与导航；新增分类不改页面骨架。
- **凭证完整**：结算信息、支付尾号、商户、里程、票据一屏可查，接近一张电子小票。
- **可维护**：备注、标签、凭证可补充，删除有确认，操作有反馈。
- **跨页一致**：金额、分类、时间、车辆、里程与账单页、首页、月度报表同源。

非目标：

- 不在本页做整笔账单编辑（分类、金额、车辆改绑）——归记账 / 编辑页。
- 不在本页做能耗趋势与深度分析——归统计页。
- 不在本页做站内路线规划、停车场实时车位、通行轨迹回放；导航只调起系统地图或外部链接。

## 2. 用户与典型场景

| 用户 | 场景 | 关注点 |
| --- | --- | --- |
| 通勤纯电车主 | 月底核对充电开销，确认某次快充的金额、站点与里程 | 金额、站点、电量、单公里成本、时间 |
| 混动 / 燃油车主 | 出差加油后把凭证分享给同行人 / 报销群 | 金额、油量、油价、支付渠道、分享内容 |
| 家庭多车用户 | 确认这笔保养记在哪辆车上，记账时和当前里程是多少 | 车辆、车牌、双里程、保养项目 |
| 报销用户 | 找到电子发票 / 小票，确认「已核验」 | 票据、核验状态、商户全称 |
| 健忘型用户 | 三天后补一句备注、加两个标签 | 备注编辑、标签、保存反馈 |
| 误记用户 | 删掉重复或错误记录 | 删除入口、二次确认、统计同步 |
| 到店用户 | 从详情直接导航到充电站 / 加油站 / 维保门店 | 导航按钮、地址、系统地图 |

关键任务（按优先级）：

1. 确认金额、状态与时间（T1）。
2. 确认车辆、双里程与结算信息（T2）。
3. 查看指标与对比（T3）。
4. 查看 / 预览票据（T4）。
5. 补备注、改标签（T5）。
6. 导航到网点（T6）。
7. 分享 / 复制 / 删除（T7）。
8. 基于这笔记录再记一笔（T8）。

| 浮层 | 底部滑入 260ms，`easeOutCubic`；遮罩淡入 |
| 内容加载 | 骨架 → 内容淡入 180ms |
| 减少动效 | 系统开启「减少动态效果」时取消缩放与淡入 |

### 4.5 适配

- 基准画布 390 × 844（设计稿 780 × 3112 @2x，内容高约 1556）。
- 内容最大宽度 448，居中；平板不拉伸单行文本。
- 顶部安全区 + 56；底部安全区 + 操作栏；内容底部预留 144。
- 指标格固定 4 列；≤ 360 宽时保持 4 列，数值允许缩小到 14 号，不换行。
- 系统字号 1.3 倍：卡片自然增高，金额缩到最小 28 号，按钮文字不截断。
- 横屏：本期不专门适配，保持竖屏布局并可滚动。

| 票据缺失 | 只显示补充入口；核验徽标按后端状态 |

## 7. 数据口径与格式化

### 7.1 字段来源

| 展示项 | 字段 | 规则 |
| --- | --- | --- |
| 标题 | `title` | 商户 / 站点 / 服务名；空则分类名 |
| 分类 | `category` | 枚举 key；决定图标与语义色 |
| 分类展示名 | `categoryLabel` | 后端组合名，如「能源补给 · 充电」；缺失用短名 |
| 分类徽标 | `categoryBadgeLabel` | 如「新能源补能」；缺失用客户端映射 |
| 副标题 | `subtitle` | 地址 / 服务描述；可空 |
| 单笔核销 | `settlementTypeLabel` | 默认「单笔核销」，退款默认「退款入账」 |
| 金额 | `amountCents` | 整数分；正数支出、负数退款；支出展示加 `-` |
| 状态 | `status.code` / `status.text` | `completed` / `refunded`；文案后端优先 |
| 交易时间 | `occurredAt` | ISO 8601；本地时区 |
| 车辆 | `vehicle.name` / `plate` / `powertrain` | 记账时快照；`bound=false` 显示「已解绑」 |
| 记账时里程 | `vehicle.odometerKm` | 记录时的里程表读数 |
| 累计总里程 | `vehicle.totalOdometerKm` | 当前累计；与记账时相同也照常展示 |
| 支付渠道 | `payment.channel` / `label` / `detail` | `detail` 为尾号等；可空 |
| 商户网点 | `merchant.name` | 可空；为空隐藏该行 |
| 指标 | `telemetry[]` | 最多 4 条：`key` / `label` / `value` / `unit` / `tone` |
| 对比 | `comparison` | `icon` / `label` / `value` / `tone`；可空 |
| 标签 | `tags` | ≤ 8，单个 ≤ 10 字 |
| 备注 | `note` | ≤ 200 字，可空 |
| 权益文案 | `settlement.discountNote` | 如「已享专属车友权益减免」；可空 |
| 票据 | `vouchers[]` | `kind` / `name` / `statusLabel` / `url` / `thumbnailUrl` |
| 核验 | `verification.verified` / `text` | 徽标「已核验 / 待核验」 |
| 导航 | `navigation` | `type` / `label` / `lat` / `lng` / `url`；可空 |

### 7.2 指标（telemetry）口径

| 分类 | 4 条指标（示例） |
| --- | --- |
| 充电 | 单公里成本 `¥0.17/km`、充入电量 `38.5 kWh`、补充续航 `+260 km`、充电时长 `42 min` |
| 加油 | 加油量 `44.6 L`、油品标号 `95# 汽油`、单升价格 `¥8.52/L`、单公里成本 `¥0.58/km` |
| 保养 | 保养项目 `基础 + 滤芯`、本次里程 `15,000 km`、距下次保养 `10,000 km`、工时/配件 `2 项 无附加` |
| 洗车 | 服务类型 `标准 水蜡洗`、服务用时 `35 min`、清洁范围 `内外 全清`、次卡核销 `1 次` |
| 停车 | 停放时长 `3h 15m`、车位分区 `B2 区-182`、计费标准 `¥10/h`、优惠抵扣 `¥15 积分` |
| 过路费 | 通行里程 `26.4 km`、通行区间 `深圳湾-福永`、ETC 折扣 `95 折`、车型费率 `客一 型车` |
| 其他 | 不展示指标格 |

- 指标由后端计算并下发展示值；客户端不根据金额 / 里程自行推导，避免与报表口径不一致。
- `tone` 只影响颜色，不影响排序；固定 4 条时保持数组顺序。
- 缺失整条数组时隐藏指标格；单条缺失由后端保证不出现（客户端仍跳过空值项）。

### 7.3 对比（comparison）口径

| 分类 | 示例 |
| --- | --- |
| 充电 | 相比同里程 92# 汽油节省约 `¥98.50` |
| 加油 | 本次百公里综合油耗测算约 `6.8 L/100km` |
| 保养 | 三电健康状态及底盘检查评分 `99.2 分 优` |
| 洗车 | 距上一次全车深度精洗已有 `21 天` |
| 停车 | 已使用会员积分抵扣停车费 `-¥15.00` |
| 过路费 | 走沿江高速相比普通地面道路节省 `约 32 分钟` |

- 对比是「解释性信息」，不是可点击指标；不做跳转。
- 文案与数值均由后端下发；客户端不生成「节省」结论。
- 对比条只占一行，值超长时省略，不换行。

### 7.4 格式化

| 场景 | 规则 | 示例 |
| --- | --- | --- |
| 支出金额 | `-` + `¥` + 千分位两位小数 | `-¥51.10` |
| 退款金额 | `+` + `¥` + 千分位两位小数 | `+¥51.10` |
| 实付金额 | 绝对值，不带符号 | `¥51.10` |
| 摘要时间 | `yyyy-MM-dd HH:mm` | `2025-05-16 13:28` |
| 结算时间 | `yyyy年MM月dd日 HH:mm:ss` | `2025年05月16日 13:28:44` |
| 里程 | 千分位整数 + ` km` | `18,426 km` |
| 支付渠道 | `label` + ` (` + `detail` + `)` | `微信支付 (尾号8812)` |
| 标签 | `#` + 文本 | `#谷电错峰` |
| 金额为 0 | `¥0.00` | `¥0.00` |

- 金额全链路整数分；展示层四舍五入到分。
- 时间按设备本地时区展示；接口返回带偏移量的 ISO 8601，客户端解析后统一格式化。

### 7.5 状态推导

- `status.code = completed` → 「已完成扣款 · 账单已入账」，绿色对勾。
- `status.code = refunded` → 「已退款 · 账单已冲正」，玫粉回退图标；结算卡标题改「退款金额」。
- 后端 `status.text` 优先；两者冲突时客户端记录埋点并按后端渲染。
- 金额正负与状态必须一致；不一致时以状态为准，并记录数据质量埋点。

## 9. 全局状态与异常

| 场景 | 处理 |
| --- | --- |
| 进入时列表已有该记录 | 用列表记录先渲染摘要 / 车辆 / 结算，再拉详情补齐指标、对比、票据、导航 |
| 进入时无记录快照 | 骨架屏，700ms 内出内容；超时显示重试 |
| 详情返回 404 | 空态「记录不存在或已被删除」，隐藏分享 / 更多，底部按钮禁用 |
| 备注保存时记录被删除 | 关闭浮层，Toast「记录已被删除」，返回账单并刷新 |
| 标签达到 8 个 | 「添加标签」置灰，点击 Toast「最多添加 8 个标签」 |
| 标签重复 | 输入框内提示「标签已存在」，保存禁用 |
| 备注全为空格 | 视为清空，保存后显示空备注占位 |
| 金额异常（超过 8 位整数） | 自动缩小字号，禁止横向滚动 |
| 车辆已删除 | 展示快照 + 「已解绑」，隐藏箭头 |
| 支付渠道未知枚举 | 显示后端 `label`；无 label 显示「其他」+ 中性圆点；完全缺失「未记录」 |
| 指标缺失 / 不足 4 条 | 按实际条数等宽排列；整条为空则隐藏 |
| 对比缺失 | 隐藏对比条，保留车辆卡其余内容 |
| 票据 URL 过期 | 预览浮层提示「凭证已过期，请重新加载」+ 重试 |
| 票据预览失败 | 保留票据卡，Toast「无法打开凭证」 |
| 导航无地图应用 | 回退浏览器；仍失败 Toast「无法打开地图，请稍后重试」 |
